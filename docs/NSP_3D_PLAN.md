방향을 결정했습니다.

A/B/C 중:

[B. 중앙 제어실 자체를 3D 환경으로 만들고,
기존 게임 로직과 모니터 UI는 최대한 유지하는 하이브리드 방식]

으로 진행해주세요.

플레이어는 중앙제어실의 의자에 앉아 있는
"실제 인간 관리자"입니다.

- 중앙제어실 공간감
- 야간근무 몰입감

- 실제 장비를 조작하는 손맛
- 플레이어가 공간에 존재한다는 느낌

을 강화하는 것입니다.

게임의 핵심 전략 로직:

FacilitySimulation
GameState
TabooRuleSystem
EventLog
Saboteur
Task 시스템
직원 배치/이동
Core/Materials/Power

등은 가능한 한 그대로 유지해주세요.

Phase 1: 3D 중앙제어실 공간 + 책상 + 모니터 2대 + 전화기 + 환풍구 + 조명 + 고정 1인칭 카메라
Phase 2: 기존 2D 시설지도/CCTV를 3D 모니터에 연결 + 클릭/드래그 같은 실제 게임 조작 연결
Phase 3: 손·팔 상호작용 + 전화/키보드 + 환경음 + 공포 연출 + 폴리싱

4. 카메라 / 플레이어 시점
==================================================

카메라는 중앙제어실 의자에 앉아 있는
인간의 눈높이입니다.

완전한 FPS 마우스룩은 만들지 않습니다.

왜냐하면 게임 핵심 조작이
마우스로 시설 지도와 직원을 조작하는 것이기 때문입니다.


기본 카메라:

- 두 모니터가 동시에 보임
- 전화기도 시야 한쪽에 들어옴
- 책상 일부가 화면 하단에 보임
- 방 뒤쪽 일부도 주변 시야에 들어옴


카메라에는 아주 작은 idle motion만 허용합니다.

예:

- 숨 쉬는 듯한 1~2px 수준의 미세 움직임
- 너무 눈에 띄는 head bob 금지
- 멀미 유발 금지


특정 오브젝트와 상호작용하면
플레이어가 직접 마우스로 고개를 돌리는 대신

Camera Tween

을 사용합니다.


예:

전화기 클릭

→ 카메라가 전화기 쪽으로 아주 조금 시선 이동
→ 팔이 등장
→ 수화기를 집음


키보드 상호작용

→ 카메라가 약간 아래로 내려감
→ 양손이 키보드로 올라옴


작업 종료

→ 카메라가 기본 위치로 부드럽게 복귀


전환 시간은 대략 0.2~0.5초 수준으로 짧게 유지해주세요.

게임 조작 흐름을 끊으면 안 됩니다.


==================================================
5. 플레이어는 반드시 "인간"으로 느껴져야 함
==================================================

중요합니다.

플레이어는 카메라만 존재하는 유령이 아닙니다.

플레이어는 실제 인간입니다.

다만 전체 몸 모델까지 만들 필요는 없습니다.

1인칭 게임처럼
필요한 순간에 팔과 손을 보여주세요.


기본적으로:

- 어두운 작업복 또는 관리자 제복 소매
- 인간형 손
- 인간형 팔

을 사용합니다.

외부 에셋은 사용하지 않아도 됩니다.

프로토타입이므로
Godot PrimitiveMesh 또는 간단한 저폴리 Mesh로 구성해도 됩니다.

다만 단순한 막대기 두 개처럼 보이지 않게
최소한:

상완 / 전완 / 손

구분이 느껴지게 해주세요.

손은 스타일라이즈된 저폴리여도 되지만
명백하게 인간 손이어야 합니다.

동물 손, 로봇 손, 비인간 형태로 만들지 마세요.

피부색/소매 Material은 나중에 교체 가능하게 분리해주세요.


==================================================
6. 손 / 팔은 평소 계속 화면을 가리지 않음
==================================================

평소에는 손이 과하게 화면을 가리지 않게 합니다.

필요하다면 화면 아래쪽에
손 일부가 아주 살짝 보이는 정도는 가능하지만,

기본적으로는 상호작용할 때 적극적으로 등장합니다.


상호작용 A — 전화 받기

전화벨 발생

→ 전화기의 작은 표시등 점멸

플레이어가 전화기를 클릭

→ 오른팔이 화면 아래에서 나옴
→ 수화기로 손을 뻗음
→ 수화기를 잡음
→ 귀 근처 위치로 이동
→ 전화 연결 SFX
→ 통화 UI 활성화


통화 종료

→ 팔이 다시 수화기를 내려놓음
→ "탁" 하는 수화기 내려놓는 소리
→ 팔이 화면 아래로 사라짐


상호작용 B — 키보드

특정 컴퓨터 입력/확인 상황에서

→ 양손이 키보드 위로 올라옴
→ 몇 번 타이핑
→ 키보드 타건음
→ 손이 다시 내려감


매번 UI 클릭할 때마다 긴 타이핑 애니메이션을 넣지는 마세요.

게임 흐름상 중요한:

- 업무 시작
- 로그 검색
- 근무 시작/종료
- 중요한 명령 입력

등에만 짧게 사용하면 됩니다.


상호작용 C — 콘솔 버튼

→ 한 손이 버튼 쪽으로 이동
→ 실제로 눌러지는 애니메이션
→ 작은 클릭/스위치 SFX


상호작용 D — 강한 공포 충격

LEVEL 3 공포 이벤트의 [쿵] 순간

→ 카메라 강하게 흔들림
→ 플레이어의 양손 또는 한 손이
   반사적으로 책상을 짚는 짧은 애니메이션

이것도 가능하면 구현해주세요.

"플레이어도 충격을 느꼈다"

는 감각을 주기 위한 것입니다.

9. 가장 중요한 기술 문제 — 모니터 입력
==================================================

기존 직원 배치/Drag & Drop UX를 훼손하면 안 됩니다.

이 부분이 3D 전환에서 가장 중요합니다.


최종 목표는:

마우스로 실제 3D 모니터 화면을 클릭
↓
RayCast
↓
화면의 UV / 로컬 좌표 계산
↓
SubViewport 내부의 2D 좌표로 변환
↓
기존 Control 입력으로 전달

입니다.


Monitor01의 직원 Drag & Drop도
가능하면 이 방식으로 동작해야 합니다.


다만 이 구현 때문에 기존 시스템을 대폭 파괴하지 마세요.

진행 순서는:

1. SubViewport가 CRT 화면에 정상 표시되는지
2. 클릭 좌표 전달
3. Drag & Drop 좌표 전달
4. 기존 배치 기능 정상 작동

순으로 단계별 테스트해주세요.


만약 3D Raycast → SubViewport Drag & Drop 전달이
예상보다 프로젝트 구조와 크게 충돌한다면

임시 대안:

"3D 모니터와 화면 위치가 정확히 일치하는
2D 입력용 투명 Control Overlay"

를 사용하는 것은 허용합니다.

단 화면 표현 자체는 3D 모니터에 있어야 합니다.

임시 Overlay를 사용했다면 반드시 보고해주세요.

13. 사운드는 매우 중요
==================================================

이 공간은 BGM보다
"시설이 살아 있다"는 환경음으로 긴장감을 만들어주세요.

가능하면 기본적으로 BGM은 사용하지 않습니다.


평상시 Ambient:

1. 환풍구 Fan Loop
2. 형광등 Hum
3. CRT / 전자 장비의 낮은 Hum
4. 멀리서 들리는 기계 소리
5. 아주 낮은 건물 진동음


특히 환풍구 소리는 반드시 구현해주세요.

중앙제어실 벽 또는 천장에 실제 Vent Mesh를 두고
그 위치에 AudioStreamPlayer3D를 배치합니다.
