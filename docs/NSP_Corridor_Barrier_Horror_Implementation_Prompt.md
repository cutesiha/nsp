## 0. 최우선 명령 — 순서, 범위, 목표

### PHASE A — 가장 먼저 구현할 1~3순위

1. **복도 시스템과 미니맵 리워크:** 지금 방 사이의 가느다란 연결선에 불과한 복도를 실제 통행 가능한 구간·차폐 가능한 구간·개체 접근 구간으로 데이터화하고, 시설 맵에서 폭과 상태를 시각화한다.
2. **실제 3D 복도와 복도 CCTV:** 중앙제어실 접근 복도와 주요 연결 복도의 3D 공간을 구성하고, 현재 오른쪽 CCTV CRT에서 작업실처럼 선택해 감시할 수 있도록 만든다.
3. **중앙제어실 차폐 시스템:** 책상 위 물리 스위치 기기의 세 번째 `PAD` 기능·명판을 `BARRIER`로 개편한다. 복도를 선택하고 차폐할 수 있어야 하며, 전력·직원 이동에 실제 영향을 준다.

**PHASE A를 완성하고** 아래 수용 테스트를 통과시킨 뒤에만 PHASE B로 넘어가세요. 코드 작성 후 보고 없이 다음 기능을 섞어 만들지 말고, 구분된 변경 내역·테스트 결과를 명확하게 정리하세요. 작업 도중 회복 불가능한 구조적 충돌이 발생하면 임의로 시스템을 갈아엎지 말고 원인과 대안을 먼저 보고하세요.

### PHASE B — PHASE A 검증 후 구현할 4~6순위

4. **FBX 괴물 3종 도입, 복도 이동, 침입, 사망, 차폐문 공격:** 사용자가 별도 첨부할 리깅·애니메이션 포함 FBX 3종을 확인 후 연동한다.
5. **다양한 독립 이상현상·공포 음향·점프스케어:** 기괴한 전화, 편향된 방향 음향, CCTV 얼굴 난입, 화면 이상 등. 일부는 순수 연출이고 일부는 실제 위협이다.
6. **관리자 공포 반응 통합:** 위협 거리·사건 종류에 따라 심장박동(BPM 변화), 거친 호흡, 화면 가장자리 붉은 비네팅, 순간 충격 효과, 자연스러운 회복/소멸을 완성한다.

> **PHASE A만 작업하는 첫 실행이라면 PHASE B는 착수하지 않아도 되지만**, 최종 목표는 이 문서의 두 단계 모두이다. 일단 A의 빌드와 실제 플레이 검증을 통과한 후 B를 순서대로 구현할 것. PHASE B에서는 FBX 원본이 아직 제공되지 않았을 때 임의의 최종 괴물 모델을 만든 척하지 말 것. 그 경우 로직·플레이스홀더까지만 만들고 원본 대기 사항을 남긴다.

**중요한 사전 조사:**

1. `RoomDef.ConnectedRoomIds`와 직원 `FindPath()`를 함께 살펴보고, 현재 직원이 통과하는 실질적인 경로를 도식화한다. `AdjacentRoomIds`를 걷는 통로로 착각하지 말 것.
2. 중앙제어실(`DeployOriginRoomId`)은 현재 직원의 일반적인 경유지로 쓰지 않는 제한 구역이다. **중앙제어실 앞 복도에 차폐문을 단 것만으로 직원 이동이 막히는 척하지 말 것.** 실제 직원 경로에 있는 차폐 구간을 따로 지정해야 한다.
3. `PowerConsumer.Sensor`를 PAD에서 BARRIER로 단순 치환하면 기존 PAD 기능, 2D 백업 전력 UI, 교육/도움말과 전력 차단 우선순위가 깨질 수 있다. 모든 사용처를 확인한 다음 전환할 것.
4. `ControlRoomAtmosphere`에는 이미 생성형 숨소리가 있으므로 **왜 현재 플레이 중 거의 들리지 않는지** (음량, SFX 버스, 실제 연결, 스트레스 조건, 오디오 반복, 설정)부터 검사한다. 기존 것을 버리고 2개를 겹쳐 재생하지 않는다.
5. `GhostHauntSystem`의 '방을 계속 관측하면 소멸' 규칙과 신설 복도 침입 개체는 **별개의 행위 유형**이다. 기존 귀신을 모두 새 시스템으로 대체하지 말 것.

PHASE A 시작 전 1회 짧은 구조 조사 요약을 남기고 바로 구현에 들어간다. 파일·메서드가 최신 로컬에서 달라졌으면 추측하지 말고 실제 위치를 찾아 연결한다.

# PHASE A — 복도·CCTV·차폐를 먼저 완성

## 2. [우선순위 1] 복도를 진짜 게임 시스템으로 승격

### 2-1. 복도 데이터 설계

현재 미니맵의 '얇은 연결선'을 **실제 통과 가능한 경로 간선(edge) 또는 구간(segment)** 으로 모델링한다.

필요 속성(이름·클래스는 프로젝트 규약에 맞게 조정 가능):

```text
CorridorSegment
  Id                  // 예: corridor_core_guard / corridor_control_north
  DisplayName         // 예: 북측 통로, 서비스 연결통로
  Endpoints           // 연결 지점/방/교차점 정보. 실제 그래프와 일치
  IsTraversable       // 일반 직원 이동 가능한 구간인지
  IsBlockable         // 차폐문이 설치된 구간인지
  BarrierId           // 연동 차폐문, 없으면 null
  CctvCameraId        // 연동 카메라, 없으면 null
  PhysicalLength      // 시각화·이동 연출용
  ThreatLaneId        // 괴물 접근용 통로(있을 경우)
  State               // OPEN / CLOSING / SEALED / OPENING / DISABLED
```

단, 기존 `RoomDef.ConnectedRoomIds`에서 유효한 통행 연결을 불필요하게 복제·불일치시키지 말고, **단일 경로 진실원(source of truth)** 을 정한다. 기존 코드가 방↔방 그래프인 경우 최소한의 `CorridorSegment` 메타데이터를 올려 기존 BFS에 **차폐된 간선을 제외하는 필터**를 제공하는 구조가 우선이다. 중앙제어실로 접근하는 괴물 전용 레인은 직원 그래프와 분리하거나 접점을 명확히 표현한다.

### 2-2. 미니맵 시각 리워크

- 기존 `FacilityMinimap.DrawCorridors()`의 3px 정도 선은 '복도'가 아니라 배선처럼 보인다. 통로가 방 사이를 잇는 **폭이 있는 띠/구조**로 보이도록 바꾼다.
- 모든 통로를 무조건 너무 굵게 하지 말고, **기본 통로 vs 주요 통로 vs 차폐 가능 통로**를 두께·윤곽·색·패턴으로 구분.
- 기존 어두운 녹청색 CRT 미니맵과 일체감 유지. 화려한 미래형 네온 노선도로 바꾸지 않는다.
- 차폐 구간은 `차폐문 마커`, 상태 문구 `OPEN/SEALED`, 차폐 중에는 붉은 막힘 표시 등을 이용한다. 작은 CRT에도 알아보기 쉬워야 한다.
- 복도에 카메라가 있으면 작은 CCTV 마커, 괴물 접근 중이면 **관측/감지된 만큼만** 위험 아이콘. 항상 괴물 좌표를 정답처럼 표시하지 않는다.
- 한 지점이 직각으로 꺾이는 경우 `CorridorElbow` 계산을 재사용하여 **직원 이동 루트·그래프·미니맵의 모양이 일치**해야 한다.
- 왼쪽 CRT의 기존 방 선택·직원 드래그·코어 표시·자재 표시·근무 종료 UI를 가리지 않는다. 클릭할 수 있는 통로의 히트박스는 방 클릭 영역과 충돌하지 않도록 우선순위 설계.
- 디버그에서 `현재 선택 통로`, `차폐 상태`, `양 끝 연결`, `CCTV target`을 확인 가능하도록.

### 2-3. 진짜 직원 이동 제약

차폐가 작동하면 **직원 이동 판정이 달라져야 한다.** 맵 색만 빨갛게 바꾸는 것은 금지.

- `FindPath()`에서 차폐된 **간선**을 경로 후보에서 제외. `SetRoomLocked()`로 방 자체를 잠가버리는 것과 혼동하지 않는다.
- 통로가 막히면 다른 열린 경로로 **우회**한다. 경로 길이가 늘면 실제로 도착이 늦어져야 한다.
- 우회 경로가 없으면 해당 직원은 통과하지 못하고 안전한 쪽에 대기하며, 선택 UI에 `차폐로 이동 불가` 또는 `경로 없음` 안내가 나온다. 순간이동, 벽 통과, 무한 이동 애니메이션 금지.
- 이동 도중 차폐: 직원이 차폐문을 통과한 것으로 처리할지/현재 쪽에서 대기시킬지 **거리·문 상태 기준**으로 일관된 판정. 중간에서 영원히 멈추면 안 된다.
- **기절자 이송**(`FaintRescueSystem`)이 같은 경로 제약을 사용해야 한다. 응급 이송 중 막히면 가능한 우회로 재탐색, 없으면 구조자가 안전한 위치에서 대기/보고하도록.
- 격리실 이송, 복귀, 재배치 및 업무 할당에도 같은 규칙 적용. 단 기존 격리 판정은 유지.
- 차폐 해제 시 대기 중인 인원은 자동으로 경로를 다시 찾거나 기존 지정 작업실로 향한다. 별도 재드래그를 강요하지 않음.
- 기본적으로 직원이 없는 공간까지 괴물 경로가 확장되어 **직원들이 무작위로 죽는 시스템**은 이번에 추가하지 않는다.
- 차폐 가능 구간 2~3개 가운데 **최소 한 구간은 실제 직원 이동 경로에 영향을 주도록** 잡고, 다른 구간은 중앙제어실 접근 위협을 막는 용도로 설계한다. 실제 맵 연결을 분석한 뒤 최종 구간을 선정하고 테스트로 증명한다.

### 2-4. 차폐용 구간 선택 기준

초기 버전에서는 **2개 권장, 최대 3개.** 첫 후보:

- 중앙제어실 북측 접근 통로: 제어실 접근 위험 차단.
- 중앙제어실 측면 서비스 통로: 제어실 접근 위험 차단.
- 시설 내 주요 연결통로 1개: 실제 직원 경로 우회·대기라는 전략적 대가 발생.

단, **3개를 전부 독립 동작시켜야 한다는 뜻은 아니다.** 초기에는 선택한 차폐문 하나만 제어하고, 활성 차폐문 수 제한을 데이터에서 조절할 수 있게 해도 된다. 실제 직원 통행에 영향 없는 허구의 연결은 만들지 말 것.

## 3. [우선순위 2] 실제 3D 복도 + 오른쪽 CRT 복도 CCTV

### 3-1. 3D 복도 모델/씬

- `scenes/rooms` 구조와 `FacilityCctvWorld`/SubViewport 관례에 맞춰 **복도용 3D 씬 또는 재사용 가능한 모듈**을 만든다.
- `다른 작업실을 잇는 지하시설의 실제 복도`임이 분명하도록: 바닥/벽/천장 재질 분리, 바닥 패널 경계, 케이블 덕트, 금속 프레임, 벽면 구역번호, 낡은 경고 라벨, 출입문, 천장등/비상등, 깊이감과 그림자.
- 작업실처럼 과도하게 넓은 네모 방을 하나 만든 뒤 '복도'라고 이름 붙이지 말 것. **길쭉한 원근, 교차부, 코너, 문, 시야 사각**으로 실제 복도 느낌을 연출.
- 차폐 가능한 구간에 금속 격벽/셔터, 구동 레일, 모터, 경고등, 관찰창/틈새, 기계식 프레임 설치. 닫힘 애니메이션과 소리, 문 접합 상태가 자연스럽게 보이게.
- 현재 게임의 저채도 지하 산업시설·아날로그 CRT 톤을 유지. 강한 네온이나 과도하게 매끈한 SF 홀로그램 금지.
- 3D 복도는 **직원 경로와 대응되는 세계를 보여주는 것**이 목적이다. 무리하게 전 시설을 하나의 거대한 연속 월드로 재구성할 필요는 없음. CCTV용 분리 씬이라도 **같은 간선 ID와 상태**를 읽어 모습이 동기화되어야 함.
- 검은 화면, 과다한 조명, 과도한 폴리곤, 텍스처 누락을 피하고 Godot Export 후 로드 테스트.

### 3-2. 복도 CCTV 선택과 재생

- `FacilityCctvWorld`는 기존에 `RoomScenes`와 `SurveillanceTargetRoomId`를 주로 사용한다. 복도는 일반 작업실이 아니므로 **가짜 RoomDef를 추가하여 업무/배치 대상에 섞지 말고**, `CorridorCameraTarget` 등의 별도 타입/등록 방식으로 지원.
- 시설 미니맵에서 복도 카메라 아이콘을 클릭하거나 CCTV 선택 UI에서 `CAM-H01 / CAM-H02` 등으로 선택 가능.
- 오른쪽 CRT에 **실제 Godot 3D 렌더** + 기존 `REC`, VHS 노이즈, 화면 흔들림, 카메라 신호 표시를 유지.
- 복도의 차폐문이 열리고 닫히는 모습과 괴물의 위치를 실제 상태대로 보여줌.
- 전력 부족으로 CCTV 채널이 꺼졌거나 CCTV 시스템이 OFFLINE이면 `NO SIGNAL` 처리. 다른 시스템과 달리 복도만 영상이 계속 보이는 버그 금지.
- CCTV가 꺼져 있어도 **괴물 이동 판정은 멈추면 안 된다.** 영상 가시성과 실제 게임 사건을 철저히 분리.
- 동시 두 개의 카메라 화면이 필요 없다면 기존 CRT 1개에 채널 전환 방식만 추가. 중앙제어실 화면 배치를 크게 바꾸지 말 것.
- 기존 '작업실 귀신 관찰 → 사라짐' 판정은 작업실 CCTV 기준으로 그대로 작동. 복도 카메라가 켜졌다고 자동 퇴치하지 않는다.

### 3-3. 복도 카메라 시야·기척

- 카메라 각도 2종 이상: 긴 복도를 보는 먼 시야, 차폐문 근처의 짧은 시야.
- 괴물이 실제로 접근 중이라면 `멀리서 흐릿함 → 중간 구간에서 또렷함 → 문 앞` 등 거리 차이가 시각적으로 드러나야 함.
- 카메라 전환 순간 엉뚱한 모델이 깜빡이거나, 개체가 다른 방으로 순간이동해 보이지 않게 카메라별 투영 좌표를 관리.
- 그림자/어둠을 이용하되 **위협에 대응 가능한 가시성**은 유지. 무작위로 못 보게 해서 죽이는 것은 금지.

## 4. [우선순위 3] 오른쪽 물리 스위치 `PAD` → `BARRIER`, 차폐 조작·전력 대가

### 4-1. 물리 장치 리워크

현재 `PowerSwitchPanel.cs`의 3개 레버는 `LIGHTING / CCTV / PAD`이고, **세 번째 PAD가 `PowerConsumer.Sensor`를 사용**한다. 이것을 단순 문자열 교체로 끝내면 안 됨.

- 기기 세 번째 명판을 `PAD`에서 `BARRIER` 또는 짧고 읽기 쉬운 `SEAL`로 변경. **기존 모델 표면의 SENSOR/PAD 글씨가 중복으로 보이지 않게** 처리.
- 기존 물리 레버 조작, 손가락으로 접촉할 때 전환, LED, 지지직·스위치 소리, 과부하 연출 유지.
- **기존 관리자 PAD의 접근·도움말·업무 기능은 삭제하거나 먹통으로 만들지 마세요.** 전력 채널 이름/종속성이 바뀌면 모든 참조를 점검하고, PAD는 적절한 독립 기기 전원/기존 시설 전원 상태에 맞춰 유지.
- `PowerConsumer.Sensor`를 BARRIER로 재사용할지 새 `Barrier` enum을 둘지는 저장·리소스·호환 관계를 검토하고 결정. 하나의 소비처가 PAD와 BARRIER를 동시에 제어하는 오작동 금지.
- 다른 채널이 부족해질 때 자동 차단 우선순위, `POWER 3/3` 표시, LED 물리 상태, 2D 백업 메뉴, 튜토리얼/설명 문구까지 일치시키기.

### 4-2. 추천 입력 UX (반드시 직관적으로)

**① 왼쪽 시설 맵 또는 오른쪽 복도 CCTV에서 차폐 가능한 구간 선택 → ② 물리 `BARRIER` 레버로 닫기/열기.**

- 차폐 불가능 복도 선택 시 `해당 통로는 차폐 불가`를 알려줌.
- 선택된 구간 이름과 `열림/닫힘/동작 중/전력 부족`을 기존 CRT 인터페이스에 작게 표시.
- 레버가 `ON`인 상태에서 다른 복도를 선택했다고 다른 문이 저절로 열리거나 닫히지 말 것. **선택 변경 = 제어 대상만 바꿈**. 이전 문을 닫은 상태로 유지할지 자동으로 안전 해제할지는 ‘최대 활성 수’ 규칙으로 명확히 설계하고 UI에 표시.
- 권장 첫 버전: `최대 동시 차폐 1개` + 개별 문 상태 표시. 레버가 *현재 선택 문*의 물리 상태와 헷갈리지 않게 전환/선택 동기화가 필수. 구현이 불안정하면 복도 선택/닫기 확인용 작은 CRT 조작 UI와 실제 레버를 분리해 안전하게 처리.
- 근무(Live) 중에만 직접 조작. 이벤트 컷인·보고서·휴게시간·타이틀·게임오버 상태에서는 입력 차단하고 버튼/레버를 정상화.
- 문 닫힘 과정 중 통로를 급격히 변경하거나 연타해도 상태가 꼬이지 않는 상태 기계(state machine) 사용.

### 4-3. 전력과 패널티 — 현재 전력 구조에 맞게 구현

**중요:** 현재 `GameState.PowerCapacity`는 쌓아 두고 소모하는 배터리가 아니라 **동시에 켜둘 수 있는 전력 채널 수**다. 따라서 “차폐 한 번 = 전력 1 소모”를 무작정 `PowerCapacity` 자체 차감으로 구현하면 기존 사고·복구 로직과 충돌한다.

초기 안전한 제안:

- 차폐가 작동 중이면 전력 소비 채널 **1슬롯을 점유**한다. 기본 근무 시작 시 `BARRIER`는 미작동, `LIGHTING`과 `CCTV` 우선 활성 상태로 시작하는 방향 검토.
- `PowerCapacity`가 떨어지면 차폐 유지와 CCTV/조명 유지 중 **플레이어 선택의 대가**가 생겨야 한다. 다른 채널을 자동으로 몰래 끄지 말고 전력 패널의 기존 규칙을 일관되게 적용.
- 차폐문 닫힘/열림에 물리적 구동 시간(예: 0.5~1.0초)과 음향. 유지 시간 상한(예: 6~10초), 짧은 재작동 제한(예: 2~4초) 등은 **운영 데이터에서 조정 가능한 값**으로. 수치는 최초 테스트값이지 확정 수치가 아님.
- **가장 큰 실질 패널티는 직원 이동 경로 차단**이다. 우회 가능할 땐 이동 시간 손해, 불가능할 땐 대기/작업 지연이 발생.
- 초기에는 유지 중 별도 무제한 자재 소모나 코어 진행도 강제 감소 등 중복 패널티를 마구 붙이지 말 것.
- 차폐 전력이 상실되면 개폐 결과가 무엇인지 명확하게 정의: 직원의 영구 고립을 막는 안전한 기본값/비상 해제/최대 시간 후 해제가 필요. 괴물 대응 실패 여부도 그 규칙에 맞춰 일관되게 판정.
- `CCTV가 나간 순간 BARRIER를 조작할 수 없어서 반드시 즉사`하는 **확정 데드락**이 생기지 않도록, 발소리·문 소리·근접 경고 등 비영상 대체 단서를 제공.

### 4-4. 기존 운영과의 상호 작용

- 직원이 차폐문 반대편에서 기다리면 `이동 지연`이 실제 업무 시작 시각과 코어/자재 생산에 반영되어야 한다.
- 직원이 긴급 이송 중이거나 문턱에 걸쳐 있을 때 문을 닫으면 부자연스러운 관통·순간이동 없이 처리.
- 괴물이 차폐문 앞에 다다랐을 때 문 상태가 `SEALED`이면 괴물은 멈추고 문을 두드리거나 긁어야 한다(이 로직은 PHASE B에서 연결).
- 플레이어가 계속 문을 닫아 두기만 해도 무적이 되는 것은 금지. 다만 폐쇄 유지 시간 및 직원 이동 비용으로 대응하게 하고, 무작위 즉사로 강제 개방하지 말 것.

# PHASE B — FBX 괴물·이상현상·관리자 공포 반응

## 5. [우선순위 4] FBX 괴물 3종과 중앙제어실 침입 시스템

### 5-1. 첨부할 FBX 확인 후 임포트

사용자가 제공할 모델은 **리깅 및 애니메이션이 이미 들어 있는 FBX 3종**임:

1. **결번자 형태의 괴물**(직원 강아지와 동일한 신원 자체를 공개하는 연출로 사용하지 말 것)
2. **기괴한 아기 괴물**
3. **기괴한 거미 괴물**

각 모델마다 실제 파일 이름·스켈레톤·애니메이션 클립 목록·루트 축·단위·메시/머티리얼·텍스처가 있는지 **임포트 후 보고**하고, 추측한 애니메이션 이름을 하드코딩하지 마세요.

- Godot 4 .NET에서 `.fbx` 임포트 지원/필요 의존성이 문제면 Godot가 안정적으로 읽는 `.glb`로 변환하여 `AnimationPlayer`/`Skeleton3D`/재질/메시 테스트. 원본은 보존.
- Idle/Walk/Run/Attack/Scare 가능 클립 확인. 없는 동작은 부드러운 코드 보간 또는 기존 클립 블렌딩으로 합리적으로 대체.
- 캐릭터 스케일/바닥 접촉/발 미끄러짐/벽 통과/루트모션 이중 적용 금지.
- 첫 번째는 **한 마리만 실제 제어실 위협형으로 완성**하여 전체 루프를 검증. 이후 나머지 2종은 고유 패턴·점프스케어 또는 관측형으로 추가.
- 한 번에 3종이 동시에 침입해 방어 불가능해지는 상황 금지. 위협형 동시 활성 수를 제한.
- **괴물 3종의 정체를 자동으로 결번 개체 강아지와 동일시하지 마세요.** 대회용 추리는 여전히 근무 기록·방해공작·심문이 담당한다.

### 5-2. 개체 상태 기계

```text
DORMANT / NOT_SPAWNED
  -> ROAMING       (복도 먼 구역 이동)
  -> APPROACHING   (중간 거리: 일부 CCTV에서 포착)
  -> NEAR          (중앙제어실 바로 인근: 소리·호흡 강화)
  -> AT_BARRIER    (차폐문 도착)
     ├─ SEALED -> BLOCKED_ATTACK (문 두드림/긁기, 침입 실패)
     └─ OPEN   -> BREACH_PREPARE (직접 침입 전조)
                    -> JUMPSCARE -> ADMIN_DEATH -> GAME_OVER
  -> RETREAT / COOLDOWN
```

- 거리/구간은 **실제 corridor graph/segment**에서 결정. CCTV를 안 보면 무조건 제자리에서 멈추는 식 금지.
- `AT_BARRIER` 상태에서 플레이어가 문을 닫는다면 판정 시각의 문 상태에 따라 공격이 취소/차단된다. 클리어하지 못한 공격이 차폐 후에도 억지로 이어지지 않도록.
- 반대로 플레이어가 문을 너무 늦게 닫아 개체가 이미 차폐선을 넘어왔다면 사전에 정의된 판정으로 처리. 순간적인 판정 바꾸기 금지.
- 공격/방어 성공, 위협 거리, 게임오버 처리는 **게임 로직 계층**에서 결정하고, CCTV 모델 이동/애니메이션은 이를 보여주기만 하도록 분리.
- Phase가 Live가 아니면 이동·사망 판정 중단, 이전 타이머/트윈/오디오 정리. 일수 전환 후 이전 괴물이 남아 있는 버그 방지.

### 5-3. 사용자가 요청한 두 가지 결정적 분기

**A. 차폐가 이미 되어 있을 때**

- 괴물이 차폐문 앞까지 접근하더라도 관리자가 죽지 않음.
- 문 너머에서 **연속으로 쿵쿵 두드림 / 금속을 길게 긁음 / 손잡이를 흔듦** 등의 직접적인 3D 음향.
- CCTV를 보면 문 앞의 괴물이 문을 긁거나 부딪히는 애니메이션. 카메라가 다른 곳을 보고 있다면 발소리·노크만 들림.
- 문과 장치에 미세한 물리 진동, 소량의 분진, 경고 LED. 과도한 파괴 연출은 필요 없음.
- 일정 시간 뒤 개체가 **후퇴하거나 다른 경로를 찾음**. 후퇴 시간·재침입 쿨다운과 동일 개체 반복 접근 횟수에 상한. 괴물이 문을 무한히 긁어 근무 종료까지 소리가 지속되지 않음.
- 차폐문을 너무 일찍 열어 버리면 이미 문 앞에 있던 개체가 다시 접근할 수 있다. 단 안전한 반응 시간은 제공.

**B. 차폐되지 않았을 때**

- 개체가 제어실 문턱에 도달해 위협이 확정되면 **플레이어 시야 바로 앞 또는 뒤**에서 비정상적인 인기척(발소리·숨소리·긁힘·속삭임)을 준다.
- 아주 짧은 인식 시간 뒤, 개체가 **순식간에 화면 앞으로 돌진하여 얼굴/상체가 시야를 강하게 차지하는 점프스케어**를 발생시킨다.
- 점프스케어와 동시에 위협적인 음향, 화면 충격, 급격한 카메라 반응 후 **관리자 사망 → 게임오버** 처리.
- '뒤에서 나타남' 변형은 시야가 뒤쪽으로 순간 회전되거나, 뒤쪽 음향 후 정면으로 급습하는 등 현재 좌석/시점 시스템에서 어색하지 않게 구현. 단순히 모델을 화면 정중앙에 1프레임 붙이는 정지 이미지가 아니라 **3D 모델이 실제로 매우 빠르게 접근**하는 연출.
- 게임패드·마우스/시점 포커스, CRT 화면 접근 상태에 따라 점프스케어가 모니터 뒤에 숨어 버리지 않도록 카메라/레이어 정리.
- 관리자 사망은 직원 죽음으로 기록되지 않음. 별도 사망 원인/결과 화면을 사용하고, 다음 날로 정상 진행되지 않게.
- 충분한 전조와 방어 창구(복도 CCTV, 거리 음향, 심장박동, 긴장 연출)를 반드시 확보. 단 한 번의 예고도 없는 랜덤 확정 사망 금지.

### 5-4. 위협별 성격 (초안, 데이터 조정 가능)

| 개체 | 권장 역할 | 특성 |
|---|---|---|
| 결번자 형태 괴물 | 느리고 불쾌한 접근형 | CCTV 말단에서 오래 서 있음, 고개 회전, 간헐적 이동, 문 긁음 |
| 아기 괴물 | 빠르고 짧은 돌진·기척 | 낮은 위치, 바닥을 긁는 소리, 짧지만 분명한 전조 |
| 거미 괴물 | 복도 코너·천장 위협 | 벽·천장 연출은 가능할 때만; 기본은 바닥/벽 인접 경로에서 안정적으로 이동 |

처음엔 **결번자 형태 1종의 완전한 경로-차폐-사망 루프**를 구현하고 다른 모델을 적재/연출에 단계적으로 편입.

### 5-5. DAY별 공포 난도 (초기 데이터 제안)

- **DAY 1:** 복도 CCTV로 위협 인지 / 접근·노크·실루엣 중심. 첫 침입에 앞서 차폐 사용 경험을 제공. 원칙적으로 치명적 침입은 비활성 또는 충분히 안내된 후 1회만.
- **DAY 2:** 첫 본격적인 사망 가능성. 실제 접근 1회 전후, 근접 음향/비네팅 명확.
- **DAY 3:** 실제 접근 1~2회까지. 신호 교란·속도 상승은 가능하되 단서 없이 즉사시키지 않음.

이 숫자는 **근무 1일의 실제 길이(현재 구현은 약 120초일 수 있으므로 반드시 로컬에서 확인)** 를 감안한 초기 예시. 정확한 시간과 등장량은 날짜별 데이터로 빼고 강제로 대규모 상수 삽입하지 마세요.

## 6. [우선순위 5] 다층 공포 이벤트 / 전화 / 공간 음향 / 점프스케어

### 6-1. 공포 이벤트를 3계열로 구분

1. **환경형(기능 영향 없음):** 귓속말, 복도 기척, 문손잡이, CRT의 미세한 잡음, 직원이 없는 CCTV 구석 실루엣.
2. **충격형(기능 영향 없음):** 괴물 얼굴이 현재 CCTV 화면을 덮거나, 여러 모니터에 순간적으로 같은 얼굴/눈동자가 비치는 강한 점프스케어, 비정상적인 직원 음성 통화, 갑작스러운 근거리 효과음.
3. **직접 위협형(실제 판정):** 복도 이동형 괴물이 중앙제어실에 접근하여 차폐 실패 시 관리자 사망. 이 계열만 실제 게임오버 가능.

**순수 공포 이벤트는 코어/직원/증거를 몰래 변경하지 마세요.** 반대로 실제 위협을 단순 장식으로 가장해서 차폐가 무의미하게 되지도 않게 한다.

### 6-2. 기괴한 전화 3종

**① 직원 목소리 변형 전화**

- 기존 직원 전화 UI/벨·수화기·스탠딩 연결을 존중한다.
- 통화 중 직원 목소리가 서서히 피치 저하, 시간 늘어짐, 좌우 채널 이동, 재생 속도 흔들림, 끊김, 금속성 잡음 등을 겪는다.
- **원래 인물의 증언으로 기록하면 안 되는 공포 연출**이라면 통화 기록에 명확히 `미확인/비정상 신호`로 구분하거나 증거 카드에 올리지 않는다. 결번자의 신원을 오판하게 만드는 거짓 공식 증거를 만들지 말 것.
- 기존 말투·그림이 유지되는 동안 점차 신호가 비틀어지는 것이 핵심.

**② 정체불명의 귀신 전화**

- `발신자 미상`, 왜곡된 목소리, 가까운 숨소리, 짧은 단어/문장. 전화 자체가 기존 근무 지시나 인터뷰 흐름을 막지 않게.
- 여유 있는 시간대와 상태에서만 발생. 중요한 직원의 구조 요청/기절 전화/게임 진행 통화를 덮어 쓰지 말 것.

**③ 무응답 전화/수화기 속 속삭임**

- 전화벨 → 수화기 들면 침묵 → 먼 곳에서 금속 긁는 소리 또는 한마디 속삭임 → 연결 종료.
- 공포 연출이 끝나면 전화 사용 상태/마우스 입력이 정상 복구되어야 함.

### 6-3. 공간 음향 / 방향 감각

- 왼쪽 귓가의 낮은 속삭임, 오른쪽 뒤의 거친 호흡, 문 바로 바깥의 금속 긁힘, 복도 끝의 아기 웃음 등의 바리에이션.
- `AudioStreamPlayer3D`로 3D 위치에 붙이거나 `AudioStreamPlayer`의 스테레오 팬 활용. **이어폰으로 들으면 분명히 좌우가 구분**되지만 스피커/모노에서도 중요한 위협을 알아들을 수 있도록 볼륨과 위치를 관리.
- 기존 `HorrorAudioDirector`와 `ControlRoomAtmosphere`의 큐/버스/쿨다운을 재사용해 중복 동시 재생 폭발을 피한다.
- 위협 방향 음향은 실제 접근 경로와 가능하면 일치. 순수 연출음은 한 공간에서 난 것처럼 들리더라도 **실제 차폐 판단에 필수적인 거짓 힌트**로 남발하지 않는다.

### 6-4. CCTV 점프스케어

- 화면 전환 또는 짧은 영상 간섭 직후 괴물 얼굴이 비정상적으로 가까이 나타나 현재 CCTV를 거의 채움.
- 강한 버전은 **현재 오른쪽 CCTV와 일부 주변 화면이 동시 간섭**되는 느낌을 주되, 좌측 시설 맵의 입력 UI·추리 자료를 항상 덮는 구조는 피한다.
- 0.2~0.7초 정도의 아주 짧은 연출 + 1~2초 자연스러운 노이즈 잔향(초기 조정값).
- 이 계열은 **관리자를 죽이지 않음 / 직원 사고 발생 없음 / 정답 증거로 기록 없음**.
- 실제 침입 사망 점프스케어와 별도로 관리.
- 서로 다른 모델/얼굴/노이즈 패턴/카메라 앵글 3종 이상. 한 영상 이미지를 하루 여러 번 똑같이 재탕하지 않는다.

### 6-5. 이벤트 스케줄·우선순위

- 이벤트 데이터를 타입, 가중치, 재사용 쿨다운, DAY 최소치, 소리 볼륨, 현재 화면 조건, 위협 위험도, 시각 효과 강도로 구분.
- **중요 전화/진짜 직원 통화, 근무 종료, 심문, 격리, 튜토리얼 중 공포 연출이 겹쳐 UI 입력을 가로채지 않도록** 차단.
- 한 번 강한 점프스케어가 나온 직후 또 다른 강한 점프스케어가 연달아 발생하지 않도록 전역 긴 이벤트 쿨다운.
- 반드시 발생해야 하는 접근 위협과 무작위 분위기 연출을 서로 다른 스케줄로 관리.
- 테스트용 특정 이벤트 강제 발생 기능을 제공하여 재현 가능하게.
- 기존 `PresenceDirector`의 무해한 형체/`HorrorAudioDirector` 랜덤 큐/`GhostHauntSystem` 작업실 귀신과 중복 발동을 확인하고 **단일 호러 오케스트레이터나 상호 배제 규칙**을 도입하되 기존 기능 삭제는 금지.

## 7. [우선순위 6] 관리자 반응: 심장박동 · 거친 호흡 · 붉은 외곽 비네팅

**가장 중요한 요구: 이벤트마다 다른 연출 조합을 적용하세요.** 어떤 일이 터지든 무조건 세 효과가 한 번에 난다면 금세 무뎌진다.

### 7-1. 공통 반응 시스템

기존 `ControlRoomAtmosphere.AddBreathStress/GaspNow`, 기존 `ControlRoom3DHorror`, 기존 오디오/오버레이를 먼저 점검·재사용한다. 관리자 긴장도는 *일관된 중앙 컨트롤러*로 관리할 것.

제안 인터페이스 예시(현재 코드에 맞게 적절히 조정):

```text
AdminFearReaction
  Trigger(reason, intensity, duration, heartbeat, breathing, redVignette, oneShotSfx)
  SetThreatProximity(distanceBand)
  ClearTransient(reason)
  ResetOnShiftEnd()
```

핵심:

- `FearReason`: `MONSTER_APPROACH`, `MONSTER_AT_DOOR`, `POWER_OUTAGE`, `CCTV_GHOST_FOUND`, `GHOST_DISPELLED`, `PARANORMAL_EVENT`, `STAFF_FAINT_DISCOVERED`, `POST_SCARE`, `DEATH` 등.
- `ThreatProximity`: `FAR / MID / NEAR / AT_DOOR / BREACHED`; 실제 괴물 레인 상태에서만 결정.
- 근접 위협은 **지속형**이며 거리가 멀어지면 자연스럽게 가라앉음.
- 전화 이상·직원 기절·화면 점프스케어는 **일회성 이벤트형**이며 n초 후 자동 해제.
- 두 이벤트가 겹치면 가장 강한 현재 효과가 유지되되 **이전 지속 위협의 상태가 사라지지 않게** 우선순위·시간 만료 관리.
- 평상 상태 복귀 시 0.5~2초 부드러운 페이드. 여러 타이머가 서로 상태를 0으로 덮어써 깜빡이는 현상 방지.
- 게임오버/근무 종료/휴게시간/타이틀·프롤로그 전환 시 효과음과 화면 연출이 남지 않도록 정리.

### 7-2. 필수 반응 매트릭스 — **그대로 구현**

| 상황 | 심장박동 | 거친 호흡 | 붉은 외곽 비네팅 | 추가 효과 / 종료 조건 |
|---|---|---|---|---|
| 괴물이 제어실에 **접근하기 시작** | **ON**, 거리 가까울수록 BPM↑ | 아직 없거나 매우 약함 | 없거나 매우 약함 | 거리가 멀어지면 심박 페이드 |
| 괴물이 **바로 근처 / 문 앞** | **빠름·강함** | **ON**, 숨 찬 소리 뚜렷 | **ON**, 화면 가장자리부터 붉음 | 위협이 사라질 때까지 지속, 그 후 자연 감쇠 |
| 괴물 도착, **차폐 완료** | 높은 상태 유지 후 감쇠 | 근접 동안 유지 | 근접 동안 유지 | 문 두드림/긁기, 후퇴하면 서서히 원상 복귀 |
| 괴물 도착, **차폐 실패** | 급격히 빨라짐 | 짧은 거친 흡기 가능 | 강해짐 | 가까운 기척 → 빠른 3D 돌진 → 점프스케어 → 관리자 사망 |

| **CCTV에서 귀신을 처음 발견** | **ON** | 기본 OFF | **ON** | **깜빡임 금지.** 외곽의 붉은 영역이 천천히 **중앙 쪽으로 다가오는** 연속 비네팅. 발견 상태 유지 중 강도 상승 |

**주의:** 직원 기절은 단순히 로그에 남긴 순간이 아니라, 플레이어가 실제로 `기절을 발견/통지받은 순간`에 1회 반응하도록 구현할 것. 현재 시스템의 `FaintRescueSystem.Fainted`와 발견/알림 경로를 조사하고 게임에 맞는 순간에 연결. 이미 알고 있던 동일 기절을 CCTV에서 다시 확인할 때 계속 새로 놀라는 버그 금지.

### 7-3. 붉은 비네팅 디자인 구체 지시

- 기본은 원래 게임 화면을 유지한 채 **전체 화면의 가장자리에서만 어두운 붉은 기운**이 번지는 비네팅. 장식적인 빨간 네모 테두리 금지.
- 반투명 그라데이션/셰이더. 중앙은 충분히 보여야 한다. 현재 모니터 작은 글자, 차폐 UI, CCTV 경고를 가릴 만큼 검거나 빨갛게 칠하지 않는다.
- 일반 공포 이벤트: 외곽이 부드럽게 올라왔다가 3~7초 내 감쇠.
- **귀신 CCTV 발견:** 붉은 영역이 `바깥 → 중앙 방향`으로 **천천히 조여 들어오는** 동작. **빨갛게 번쩍-꺼짐 반복 금지**. 관찰 지속 시간에 따라 한계 강도까지 다가온 뒤 귀신 퇴장 시 서서히 원위치.
- **정전:** 심박 + 외곽 적색에 집중하고 숨소리 트리거는 추가하지 않는다(이미 다른 원인으로 숨을 쉬는 상태라면 강제 뮤트하지 않음).
- 문 앞 근접: 비네팅이 심박과 아주 약하게 호응할 수 있지만 발작을 유도하는 빠른 명멸 대신 **연속적인 농도·면적 변화** 중심으로.
- 전체 UI 상단에 오버레이하되 마우스/레이/버튼 입력을 절대 가로채지 않음. 화면 배율/해상도 변경에도 모양 유지.

### 7-4. 심장박동 음향 — BPM 변화 + 대체 파일 지원

가능하면 **Claude Code가 실제로 Godot에서 재생 가능한 심장박동을 프로시저럴 오디오로 생성**해 주세요. 가능하며, 불가능하다고 가정하고 생략하지 마세요.

- 예: 2회 짧은 저주파 타격 `둥-둥` 패턴 + 쉬는 구간. 심박 수에 따라 **비트 간 간격이 바뀌어야** 한다. 단순 PitchScale만 올려 듣기 싫게 왜곡시키는 방식 금지.
- `FAR 75~90 BPM`, `MID 95~115 BPM`, `NEAR 120~145 BPM`, `AT_DOOR 145~170 BPM` 정도를 첫 테스트 범위로 제안. 실제 숫자는 후에 조절.
- 사운드 재생 자체는 낮은 주파수에 중심을 두되, 작은 스피커에서도 약하게 들리는 타격 성분을 포함. 지나친 서브베이스·클리핑 금지.
- 볼륨은 거리에 따라 부드럽게 증가. 좌우 귓속말, 경고음, 직원 대사보다 모든 시간을 덮지 않게 믹싱.
- 기존 `Sfx`의 버스/볼륨 설정을 사용. 루프가 중첩 재시작하거나 이전 심박이 끊기지 않도록.
- **프로시저럴 생성 품질이 좋지 않으면** `res://assets/audio/sfx/admin_heartbeat.wav` 파일을 나중에 사용자가 넣을 수 있도록 **명확한 교체 경로**를 마련. 파일이 없을 때도 크래시가 아니라 프로시저럴/임시 폴백 사용.
- 이 경우 `admin_heartbeat.wav`가 없다고 구현 전체를 포기하지 말고, **파일이 필요하다면 마지막 보고에 정확한 경로·파일명·루프 조건·권장 길이**를 명시할 것.

### 7-5. 거친 호흡

- 기존 `ControlRoomAtmosphere`에서 호흡은 이미 `MakeBreathStream()`으로 필터 노이즈 기반 루프가 생성되고 `AddBreathStress()`가 있다. 사용자가 **지금 플레이에서 호흡이 거의 안 느껴진다고 지적**했으므로:
  1. 루프가 실제 재생 중인지
  2. `Sfx` 오디오 버스·사용자 음량 설정이 정상인지
  3. `BreathBaseDb`가 지나치게 작은지
  4. `AddBreathStress`가 관련 이벤트에서 호출되는지
  5. `GamePhase.Live`/검사 씬에서 구독이 빠지지 않는지
  6. 기존 앰비언스 소리가 숨을 덮는지
  확인 후 보완.
- `NEAR`, `AT_DOOR`는 숨 찬 호흡이 분명하게 들리게, 환경 이상현상은 몇 초간 들렸다 사라지게.
- 위험하지 않은 평상 상태에서는 숨소리 거의 없음. 계속 과호흡해서 피로감을 주지 않음.
- 동일한 유형의 호흡 루프를 두 개 동시에 중첩 생성하지 않음.
- **재침입·연속 고조 상태에는 근접 거리와 무관하게** 짧은 거친 호흡을 독립 발생 가능하게 구현.
- 별도 `admin_panic_breath.wav`가 있다면 고조 상태에만 사용, 없으면 기존 프로시저럴 루프를 개선해 사용.

### 7-6. 기존 CCTV 귀신 발견/소멸 애니메이션

- `GhostHauntSystem`의 기존 'CCTV로 일정 시간 계속 보면 소멸' 규칙은 유지.
- **최초 관찰이 실제 화면에 뜬 시점**에 심박과 붉은 비네팅의 중앙 접근이 시작됨. 미니맵에서 방을 선택만 하고 CCTV가 꺼져 있으면 발동하지 말 것.
- 관찰이 계속되면 기존 퇴치 게이지를 사용. 발견 이벤트가 매 프레임 반복 발화되지 않게 추적.
- 귀신이 소멸(`Dispelled`)했을 때 기존 `FacilityCctvWorld`의 `_ghostVanishing`, 소멸 연출 등을 점검해 **알파 페이드/디졸브/파티클 등 자연스러운 소멸**로 처리. 클립이 끊기는 즉시 메시가 1프레임에 사라지는 현상 금지.
- 소멸하면 심장박동과 비네팅 역시 자연스럽게 줄어듦. 다른 괴물이 문 앞에 있다면 해당 지속 위협은 여전히 남아야 함.
- 기존 퇴치 효과음, 사고 판정, 직원 반응도 유지.

## 8. 사고 빈도와 모드별 적용 범위

사용자는 **추리·격리 밸런스 조정은 맨 마지막에 하기로 결정**했습니다. 그러므로 이번 단계에서 코어 복구량, 사보타주 진실성, 직원 증언 로직, 격리 보상·패널티를 변경하지 않습니다.

다만 복도 생존 위협이 새로 생기므로 **일반 무작위 작업실 사고 빈도**는 대회용 모드에서만 소폭 하향할 수 있도록 **운영 프로필 파라미터/배율을 준비**하고, 최초 값은 완만하게 보수적으로 조정하세요.

- 특정 사고 타입만 조절: 일상 고장/일반 랜덤 작업 사고 ↓.
- **스토리·튜토리얼 강제 발생 이벤트, 기존 결번 사보타주, 필수 추리 단서는 임의로 삭제하거나 우연히 더 적게 등장하도록 조절하지 말 것.**
- 실제 사고 감소 비율은 기존 각 날짜의 발생량을 측정한 뒤 정하고, 일률적으로 전부 반토막 내지 말 것.
- 기본 5일 모드는 기존 난도 유지. 대회용 3일은 별도 프로필/모드 플래그 기반.
- 새 괴물 위협이 강할수록 운영 부담이 커지므로 **복도 공격 쿨다운·사고 빈도·짧은 근무 시간**을 통합 테스트하여 과부하 방지.
- 모드 시스템이 아직 없는 경우 설계용 설정값을 먼저 분리하고, 기존 5일 본편과 대회용 3일 설정이 섞이지 않도록 최소 변경으로 도입. 단 타이틀 메뉴를 전면 재작성하지 말 것.

## 9. 기술 원칙과 예외 처리 — 절대 생략 금지

### 9-1. 판정과 연출 분리

- **Corridor/Barrier/Monster simulation**: 실제 상태·길찾기·위협 도달·사망 여부를 결정.
- **FacilityMinimap/CCTV 3D World/3D Controls**: 상태를 읽어 보여주고 입력만 전달.
- **AdminFearReaction/Sfx/Overlay**: 사운드 및 화면 연출. 플레이어 스트레스 수치를 승패에 연결하지 않음.
- 작업실 귀신(`GhostHauntSystem`)의 퇴치와 중앙제어실 침입형 괴물은 규칙을 혼동하지 말 것.

### 9-2. 재시작·정리

- 새 게임/근무 시작/근무 종료/휴게시간/사망/타이틀 복귀 때 모든 새 시스템과 구독·타이머·트윈·오디오 상태 정리.
- 특정 이벤트 종료 후 붉은 화면이 남는 현상, 오래된 심박음이 지속되는 현상, 차폐문이 전날부터 닫혀 있는 현상, 이전 괴물이 CCTV에 남는 현상 금지.
- 저장/로드가 있으면 관련 상태를 안전하게 직렬화/재구성. 없다면 저장 시스템을 갑자기 신설하지 말고 정상 재시작 동작부터 보장.

### 9-3. 전력/입력 충돌

- `GameState.TryTogglePower`, `PowerSwitchPanel.BeginToggle/DoToggle`, `ControlRoom3DController.IsInputLocked` 사용 규칙과 충돌 금지.
- PAD가 세 번째 스위치 개편 때문에 사라지지 않았는지, 기존 `Sensor` 채널 참조가 남아 이상한 전력 차단을 만들지 않는지 전역 검색.
- CRT에 포커스 중인 상태와 3D 전력 패널 확대 중인 상태 모두에서 키·마우스·레이 입력 충돌 테스트.
- 시네마틱 점프스케어 중 단말기 클릭/전화 받기/근무 종료 같은 입력이 유령 연출 위로 새어 들어오지 않게.

### 9-4. 성능 및 공포 접근성

- CCTV가 여러 개라도 항상 보이지 않는 카메라를 전부 고화질 실시간 렌더하지 않음. 활성 피드 위주로 사용.
- FBX 3종은 가시거리·활성 방 기준으로 업데이트하고, 리깅/파티클/조명 성능 점검.
- 강한 점프스케어의 음량은 마스터/SFX 설정을 무시하지 않음.
- 가능하면 설정 옵션으로 `점프스케어 볼륨`, `카메라 흔들림`, `광과민성 유발할 수 있는 빠른 점멸`을 줄일 수 있게 하되, **선호를 이유로 공포 기능을 임의로 제거하지는 말 것**.
- 화면 붉은 비네팅은 급격한 깜빡임보다 감쇠형으로 처리하고 CRT 가독성을 유지.

## 10. 자동·수동 수용 테스트 (반드시 수행)

### A단계 테스트

1. 시설 지도에 복도가 폭 있는 구간으로 나타난다. 방 선택, 직원 아이콘 클릭·드래그가 정상.
2. 주요 복도 2개 이상을 오른쪽 CCTV로 보고 채널 전환 가능. 신호 끊김·전력 차단 시 올바른 `NO SIGNAL`.
3. BARRIER를 사용해 문을 닫으면 **복도 3D 문 + 왼쪽 미니맵 상태 + 직원 경로**가 동시에 변경.
4. 출발지와 목적지 사이 하나의 경로만 있는 직원이 차폐로 대기한다; 우회 경로가 있으면 우회하고 더 늦게 도착한다.
5. 이동 도중 문 닫기, 개방, 전력 손실, 문 재선택 연타에도 멈춤/순간이동/게임 크래시 없음.
6. 기절자 구조 이동 및 격리/복귀 시나리오에 새 경로 제약이 적용됨. 이송자가 벽을 뚫지 않음.
7. PAD 관련 기존 화면·기능이 유지됨. 물리 패널 레버·LED·전력 슬롯 상태와 맞음.
8. DAY 0/기본 모드에서 새 기능 때문에 진행이 막히지 않음.

### B단계 테스트

9. 결번자 형태 괴물 1종이 먼 복도→가까운 복도→문 앞에 도착하고, CCTV로 일부 단계 관찰 가능.
10. 차폐 **닫힘**: 괴물이 문 두드림/긁기 후 물러나며 관리자 생존. 반복 재생/무한 소리 없음.
11. 차폐 **열림**: 근접 기척→3D 돌진→점프스케어→관리자 사망→게임오버.
12. CCTV를 보고 있지 않아도 괴물 실제 접근 판정이 진행되지만, 3D 소리·심박 등 방어 단서가 존재.
13. 정전 중 CCTV와 미니맵 소등 + **빨간 비네팅과 빠른 심박만** (정전 단독 트리거로 숨소리 추가하지 않음).
14. 기괴한 직원 전화/귀신 전화/좌우 속삭임/괴물 얼굴 CCTV 난입이 실제 게임에 직접 불이익을 주지 않음.
15. 직원 기절을 처음 발견하면 **적색 충격 + 무서운 SFX 단 1회**, 같은 인원을 다시 보는 것만으로 재발동 안 함.
16. CCTV에서 기존 귀신 발견 시 **외곽 적색이 중앙으로 서서히 진입 + 심박**. 귀신 퇴치 시 **귀신 모델도 페이드, 관리자 효과도 감쇠**.
17. 괴물 원거리→근거리→문 앞 이동에 맞춰 심박 BPM/호흡/붉은 비네팅이 다르게 반응.
18. 근접 위험이 사라졌는데 심박과 호흡이 영원히 지속되지 않음. 다른 사건과 겹쳐도 올바른 우선순위로 감쇠.
19. 전화·심문·컷신·휴게시간·리셋 중 이벤트가 끼어들어 입력이 잠기거나 로직이 꼬이지 않음.
20. 다른 직원 5명이 정상으로 취급되고 강아지 고정 결번이라는 대회용 추리 규칙에 새 공포 시스템이 멋대로 간섭하지 않음.
21. 최종 `dotnet build`, Godot 씬 임포트 오류, headless 가능 테스트, 실제 1920×1080 플레이 수동 점검.

## 11. 매 단계 완료 시 보고 형식

작업 종료 시 다음 항목을 짧고 정확하게 알려 주세요.

1. **단계**: PHASE A(1~3) / PHASE B(4~6) 중 어디까지 완료했는가.
2. **수정 파일 / 새 파일**: 파일 경로 나열.
3. **구조 변경**: 복도 source of truth, 직원 경로 차단 방식, 전력 소비/차폐 상태 기계의 실제 설계.
4. **플레이 확인**: 화면에서 정확히 무엇이 보이고 무엇을 누르면 어떻게 동작하는가.
5. **FBX 상태**: 3종 실제 로드 성공 여부, 각 애니메이션 목록, 실패 시 이유.

## 12. 최종 한 문장 목표

**야간근무지침은 직원의 위치와 거짓말을 감시하는 관제실 게임인 동시에, 관리자인 나 자신이 복도를 CCTV로 살피고 전력을 희생해 차폐문을 내리면서 살아남아야 하는 3일짜리 공포 추리 게임이 되어야 한다.**

복도는 진짜 길이어야 하고, 차폐는 진짜 통행과 전력을 바꿔야 하며, 괴물은 가까워질수록 심박과 숨소리를 바꾸고, 문이 닫혀 있으면 두드리거나 긁고, 열려 있으면 직접 시야로 돌진하여 관리자를 죽여야 합니다. 그 밖의 귀신 전화·CCTV 얼굴·방향성 음향은 추리를 방해하지 않는 강력한 공포 연출이어야 합니다.
