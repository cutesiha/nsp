# 야간근무지침 — DAY 1 PROTOTYPE PLAN

> 목표: 2일치를 얕게 만드는 것이 아니라, **DAY 1 하루를 4개 전략 시스템이 전부 맞물린 상태로 완벽하게 구현**한다.
> 얕은 5일보다 완벽한 하루가 심사(도전성·구현가능성·완성도)에서 유리하다.
> 반드시 `GAME_DESIGN.md`, `DEVELOPMENT_RULES.md`, `MANAGEMENT_STRATEGY.md`를 함께 읽고 따른다.

## 0. 팀 / 실행 방식

- 프로그래밍: 1인 (Loka). 그래픽: 2인.
- 그래픽 아트가 준비되기 전까지 **모든 화면은 임시 도형 + 텍스트**로 만든다. 임의의 완성형 디자인을 만들지 않는다.
- 에이전트는 아래 PHASE를 **순서대로 연속 실행**한다. 각 PHASE의 완료 기준은 에이전트가 스스로 빌드/실행/로그로 검증한다.
- **단계마다 멈춰서 사용자 플레이테스트를 받지 않는다.** 사용자에게 질문하는 경우는 오직 `DEVELOPMENT_RULES.md` #7처럼 **설계가 모호할 때뿐**이다.
- 통합 검증은 맨 마지막에 한 번만 한다(섹션 5).

## 1. DAY 1 슬라이스가 답해야 할 것

DAY 1 빌드가 끝났을 때 아래에 답할 수 있어야 한다. 각 질문은 4개 전략 시스템과 연결된다.

1. 금기와 코어 요구가 충돌해서 근무표가 **제약 퍼즐**이 되는가? (시스템 ①)
2. 부족한 전력/시선을 어디 쓸지 **트레이드오프 고민**이 생기는가? (시스템 ②)
3. 사보타주가 실제로 코어를 깎고, 로그·CCTV·진술 **교차검증**으로 범인이 좁혀지는가? (시스템 ③)
4. 내가 만든 사각·실수 때문에 살인마가 움직이는가? (시스템 ④)
5. 격리가 "확신 vs 노동력 손실"의 **기댓값 판단**이 되는가? (시스템 ③)

**이 다섯이 재미없으면 그래픽·스토리를 붙이기 전에 기획을 수정한다.**

## 4. DAY 1 흐름 (완성 목표)

1. **근무 준비** — 활성 금기 2개(충돌형) 확인, 직원 4명 능력치·스트레스 확인, 코어 목표 확인
2. **근무표 작성** — 코어 요구와 금기가 충돌하므로 우회 배치를 설계해야 함 (시스템 ①)
3. **실시간 운영** — 직원 이동·업무, 전력·시선 예산 배분(시스템 ②), 사보타주 발생, 조건 맞으면 살인 1회(시스템 ④)
4. **관리자 개입** — 통화 연결 / 재배치 / 봉쇄 / 업무 우선도 / 전력 배분
5. **근무 정산** — 코어 진행도(사보타주 감소분 포함) / 사건 로그 / 금기 위반 / 생존 직원
6. **직원 대화** — Claude(또는 fallback)로 질문, 교차검증용 진술 확보 (시스템 ③)
7. **격리 선택** — 직원 1명 격리 (오격리 시 노동력 손실 반영)
8. **PROTOTYPE RESULT**

## 5. 제작 순서 (에이전트 실행용)

각 PHASE는 순서대로 연속 실행한다. 완료 기준은 에이전트가 스스로 검증한다.

### PHASE 0 — 프로젝트 뼈대
- 폴더 구조 생성
- 역할 분리된 뼈대: `GameState`(세션/코어/자원/승패) · `FacilitySimulation`(이동/업무/방/실시간사건) · `TabooRuleSystem`(활성 금기/위반 검사/결과 요청) · `AIService`(Claude 통신 전담) · 공용 `Config` · 공용 `EventLog`
- 문서 4종(`GAME_DESIGN` / `DEVELOPMENT_RULES` / `DAY1_PROTOTYPE` / `MANAGEMENT_STRATEGY`) 포함
- **완료 기준:** 빈 프로젝트가 정상 실행되고 각 시스템의 public API 껍데기가 서로 겹치지 않게 존재한다.

### PHASE 1 — 데이터 (직원 / 방 / 금기 / 업무)
화면보다 데이터를 먼저 만든다. 전부 데이터 주도(하드코딩 금지).

- 직원 4명 리소스: `codename / 기술·담력·관찰 / stress / personality_lines(3) / role / 현재위치 / 현재업무 / alive / isolated`
- 방 4~5개 리소스: `room_id / 연결 / 전력상태 / 잠금상태`
- 금기 3개 정의 (그중 **2개는 코어 요구와 충돌하도록** 설계): `taboo_id / condition_type / condition_params / consequence_type / consequence_params`
- 업무 정의: `업무 / room / 필요 인원 / 요구 능력치 / 우선도` (일부 업무는 금기와 겹치게)
- `Config`: 최대 직원 수, 스트레스 최대치, 전력 예산 총량, 각 소비처 비용, API timeout, 이동 속도 등 매직 넘버 전부
- **완료 기준:** 코드/데이터에서 직원·방·금기·업무 상태를 생성/조회/변경할 수 있고, 코어 최적 배치가 금기와 충돌하는 조합이 데이터에 존재한다.

### PHASE 2 — 시설 지도 + 직원 이동
- MONITOR 01용 임시 지도, 방을 네모 박스로, 직원 아이콘 표시
- 업무 목적지로 실제 이동, 도착 후 업무 시작
- **완료 기준:** 근무표에 따라 직원들이 방 사이를 이동하고 업무를 수행한다.

### PHASE 3 — 근무표 + 업무 진행 + 코어
- 직원에게 업무 배정, 요구 능력치가 진행도에 반영
- 코어 수리 업무, 자재/전력 최소 처리
- **완료 기준:** 어떤 직원을 배치했는지에 따라 완료 속도/성공이 달라진다.

### PHASE 4 — 금기 2개 (충돌형) — 시스템 ①
- 조건 검사 / 위험 표시 / 실제 위반 / 결과(정전·CCTV 단절·통로 잠금 등) / 로그 기록
- 이 2개 금기는 그날 코어 최적 배치와 **직접 모순**되게 한다.
- **완료 기준:** 근무표가 "풀린 문제"가 아니라 우회로를 찾아야 하는 제약 퍼즐이 된다. (같은 금기 결과를 여러 씬에서 중복 구현하지 않는다.)

### PHASE 5 — 전력 + 시선 제로섬 예산 — 시스템 ②
- 전력 예산 총량(Config)과 소비처(CCTV 감시 / 환기·수리 / 조명)
- 배분 UI, 예산은 항상 부족하게
- 배분 결과가 업무 속도·금기 위험·CCTV 가시성에 실제 반영
- **완료 기준:** 감시와 운영이 같은 예산을 두고 경쟁하며, 감시를 켜면 어딘가 사각이 생긴다.

### PHASE 6 — 두 모니터 + CCTV
- MONITOR 01에서 방 클릭 → MONITOR 02에 해당 방 CCTV 표시 (직원·사건)
- 각 모니터 클릭 확대 / 취소 시 복귀
- **완료 기준:** 지도에서 이상을 발견하고 CCTV로 확인하는 흐름이 자연스럽다.

### PHASE 7 — 실시간 관리자 개입
- 통화 연결 / 재배치 / 구역 봉쇄 / 업무 우선도 (전력 배분은 PHASE 5와 연결)
- 재배치 비용은 이동 시간 + 기존 작업 진행 손실 (별도 행동 포인트 금지)
- **완료 기준:** 계획대로 흘러가지 않는 상황을 플레이어가 실시간으로 수정할 수 있다.

### PHASE 8 — 공용 로그 + 교차검증 증거 — 시스템 ③ 토대
- 공용 `EventLog`에 기록: 방 입장/퇴장, 업무 시작/종료, 재배치, 금기 위반, 정전, CCTV 단절, 거짓 지시가 실제 행동으로 이어진 경우, 사망/격리
- 각 NPC에게는 그 NPC가 알 수 있는 정보만 별도 필터링
- **완료 기준:** 로그·CCTV·진술을 교차하면 모순이 드러나는 구조가 성립한다.

### PHASE 9 — 파괴공작자 로컬 로직 — 시스템 ③·④
- 직원 4명 중 1명을 숨은 파괴공작자로 지정 (초기에는 Claude 없이 로컬 규칙)
- 후보 행동: 정상 업무 / 허가되지 않은 이동 / 거짓 지시 / 설비 방해 / **코어 진행도 감소(사보타주)**
- 조건(사각·금기 위반·직원 고립)이 맞을 때만 **살인 시도 1회** 허용
- 사보타주·거짓말은 반드시 로그/CCTV에 **모순 흔적**을 남긴다
- 살인 가능 조건·성공 여부는 Godot가 판정 (Claude 반환을 그대로 실행하지 않음)
- **완료 기준:** 플레이어가 "쟤 왜 저기 가지?"라고 의심하게 되고, 방치 시 사보타주로 코어가 실제로 깎인다.

### PHASE 10 — Claude 직원 대화 (fallback 필수)
- 직원 선택 → 대화. Claude에 전달: `코드네임 / 성격 3문장 / 현재 스트레스 / 오늘 업무 / 직접 목격한 사건 / 최근 대화 요약`
- 살인마인 경우에만 숨은 목적·허용 행동 추가
- 말풍선 타이핑 출력, 매 프레임/전 직원 주기 호출 금지, 필요한 순간에만 호출
- **API 실패 시 로컬 fallback 대사** (timeout/retry/JSON 파싱 실패 안전 처리)
- **완료 기준:** NPC마다 성격과 아는 정보가 다르게 느껴지고, 대화가 교차검증에 실제로 도움이 된다. 인터넷이 끊겨도 빌드가 멈추지 않는다.

### PHASE 11 — 정산 + 격리 + RESULT — 시스템 ③ 완성
- 정산: 코어 진행도(사보타주 감소 포함) / 사건 로그 / 금기 위반 / 생존 직원 / 자재
- 격리: 직원 1명 선택. **오격리 시 노동력 손실이 실제로 반영**되어 기댓값 판단이 되게 함
- 진범 여부를 즉시 "정답"으로 알려주지 않는다
- PROTOTYPE RESULT 화면 출력
- **완료 기준:** `근무 준비 → 근무표 → 실시간 운영 → 정산 → 대화 → 격리 → RESULT` 한 사이클이 4개 시스템이 맞물린 채 완주한다.

## 6. 통합 검증 (마지막에 한 번만)

전체 빌드 완성 후, 사용자 본인 + 다른 테스트 플레이어에게 한 번만 확인한다.

- 금기 때문에 근무표를 30초 이상 고민한 순간이 있었는가? (①)
- 전력·시선 배분에서 "이걸 켜면 저게 죽는다" 트레이드오프가 있었는가? (②)
- 로그·CCTV·진술을 교차해서 범인을 좁혀갔는가? 격리가 도박이 아니라 기댓값 판단이었는가? (③)
- 내가 낸 사각·실수 때문에 살인마가 움직였는가? (④)
- **한 판 더 해보고 싶은가?**

**마지막 질문이 NO면 콘텐츠를 늘리기 전에 핵심 루프를 수정한다.**

## 7. DAY 1에서 만들지 않을 것

- 직원 6명 전체 / 2일 이상 / 자유 타일 건설 / 시설 업그레이드
- 금기 4개 이상 동시 / 복잡한 살인 연출 / 여러 엔딩 / 개별 장편 스토리
- 추가 게이지(피로·호감도·신뢰도·정신력) / 세이브 고도화 / 완성형 아트·사운드
- 살인마 Claude 행동 판단 (먼저 로컬 규칙으로 성립시키고, 재미가 확인되면 그때 얹는다)
