# 야간근무지침 — MANAGEMENT / STRATEGY DESIGN

> AI 에이전트가 이 게임의 **전략성**을 어떻게 구현해야 하는지 이해하기 위한 문서다.
> 여기 있는 4개 시스템은 **새로운 게이지나 새로운 시스템이 아니다.**
> `GAME_DESIGN.md`의 기존 3기둥(금기 / 코어 복구 / 사회적 추리)을 **서로 충돌시키는 규칙**이다.
> `DEVELOPMENT_RULES.md`(SSoT, 데이터 주도, Claude/Godot 판정 분리)를 그대로 따른다.

## 0. 왜 이 문서가 필요한가

현재 기획은 금기 / 코어 복구 / 추리가 **평행선으로 따로 돈다.** 서로 안 부딪혀서 배치가 한 번 배우면 끝나는 암기가 되고, 추리는 안 해도 클리어 가능한 곁다리가 된다.

이 문서의 목표는 **세 기둥을 강제로 맞물리게 해서** "고난이도 + 논리적 사고 + 자원 트레이드오프 + 심리전"을 만드는 것이다.

### 절대 원칙
- **새 수치 상태를 만들지 않는다.** 스트레스 1개 유지. 피로/호감도/신뢰도/정신력 금지.
- **이 4개 시스템은 전부 LLM(Claude) 없이도 완전히 성립해야 한다.** Claude는 그 위에 사회적 질감만 얹는다. (심사용 빌드에서 인터넷이 끊겨도 전략·추리가 무너지면 안 된다.)
- 재미는 시스템 추가가 아니라 **기존 시스템끼리의 충돌**에서 나온다.

## 1. 시스템 ① — 금기 × 코어 복구 충돌 (제약 만족 퍼즐)

### 의도
근무표 짜기를 "이미 풀린 문제"에서 **제약 만족 퍼즐**로 바꾼다. 이게 순수 논리·전략 파트다.

### 규칙
그날의 **코어 복구 최적 배치**가 그날의 **활성 금기 2개와 직접 모순되도록** 콘텐츠를 설계한다.

- 예: 코어 수리 업무 = `연구실에 2명 필요` + 활성 금기 = `연구실에 동시에 2명 이상 배치 금지`
- 즉 "가장 효율적인 배치"를 그대로 쓰면 반드시 금기를 위반하게 만든다.

### 플레이어에게 열려야 하는 우회로
플레이어는 정답이 막힌 상태에서 스스로 대안을 찾아야 한다.

- 시간차로 1명씩 순차 투입 (효율 손해, 금기 회피)
- 금기 위반을 감수하고 그 결과를 운영으로 수습
- 능력치가 낮아도 금기에 안 걸리는 직원으로 우회
- 다른 방 업무를 늦추고 인력을 재배치

### 데이터 함의
- 업무 정의(`room`, `필요 인원`, `요구 능력치`)와 금기 조건(`condition_type`, `condition_params`)이 **겹치도록 데이터를 큐레이션**한다.
- 충돌은 랜덤이 아니라 **의도적으로 설계**한다. 금기를 무작위로 뽑아서 우연히 안 겹치게 두면 이 시스템은 죽는다.
- if/else 하드코딩 금지. 전부 데이터로.

### 판정 / 하지 말 것
- 위반 여부와 결과는 Godot가 판정한다. 결과는 예측 가능한 운영 사건이어야 한다. (`랜덤 체력 -20` 금지)
- 매일 금기 조합이 바뀌므로 매일 다른 논리 퍼즐이 된다. 이 점을 데이터 설계에서 보장한다.

## 2. 시스템 ② — 전력 + 시선 제로섬 예산

### 의도
**범인을 감시하는 행위 = 시설 운영 효율을 깎는 행위**가 되게 한다. 부족한 자원을 어디에 쓸지가 매일의 전략 핵심이 된다.

### 규칙
전력과 CCTV 시선(관찰 자원)을 **같은 제한된 예산 풀**에서 소비하게 한다.

- CCTV는 이미 한 번에 한 방만 실시간으로 본다(MONITOR 02). 이 "한 번에 하나"라는 제약을 전력 예산과 묶는다.
- 세 소비처가 같은 예산을 두고 경쟁한다:
  - 의심되는 방 감시 (범인 잡기)
  - 환기 / 수리 전력 (코어 복구 효율)
  - 조명 / 전력 상태 (일부 금기가 이 상태를 참조함 → 예: `적색등 아래 코드네임 금지`)

### 데이터 함의
- 전력 예산 총량은 공용 Config에서 소유한다. 각 소비처의 비용도 Config/데이터. **매직 넘버 금지.**
- 예산은 항상 **부족하게** 설정한다. 무한 전력이면 이 시스템 전체가 무의미해진다.

### 판정 / 하지 말 것
- 전력 배분 결과가 업무 속도 / 금기 위험 / CCTV 가시성에 **실제로 반영**되어야 한다. 표시만 하고 효과 없으면 안 된다.
- 판정은 Godot.

## 3. 시스템 ③ — 추리에 이빨 달기 (격리 = 기댓값 결정)

### 의도
추리를 "안 해도 되는 곁다리"에서 **"안 하면 진다"로 승격**시킨다. 이게 논리적 사고의 핵심 무대다.

### 규칙 A — 사보타주가 실제로 코어를 깎는다
- 파괴공작자의 방해는 **코어 진행도를 물리적으로 감소**시킨다.
- 즉 범인을 방치하면 DAY 5 100% 달성이 물리적으로 어려워진다. → 추리가 필수가 된다.

### 규칙 B — 오격리는 노동력 손실
- 엉뚱한 직원을 격리하면 인력이 빠져 코어 수리가 늦어진다.
- 결과적으로 격리 결정은 **"내 의심이 이 노동력 손실을 감수할 만큼 확실한가?"** 라는 기댓값 판단이 된다.

### 증거 설계 (가장 중요)
로그 + CCTV + NPC 진술을 **교차검증**해야만 모순이 드러나게 한다.

- 사보타주는 반드시 **물리적으로 / 증언상 모순되는 흔적**을 남긴다.
  - 예: "발전실에 있었다"고 말했는데 그 시간 금기로 잠긴 복도를 건넌 기록이 로그에 찍힘
  - 예: 특정 방의 수리 진행도가 음수 = 사보타주가 일어났다는 증거
- 추론 방식은 **모순의 존재/부자연스러운 부재로 범인을 좁히는 것**이다. (필적에서 이미 잘 뽑았던 '모순의 부자연스러운 부재' 메커니즘을 실시간 경영 프레임으로 이식하는 것.)

### 판정 / 하지 말 것
- 진위 판정(누가 진범인가, 사보타주가 실제로 일어났는가)은 Godot가 한다. Claude는 진술 표현만 담당한다.
- **즉시 "정답"을 알려주지 않는다.** 진범을 격리해도 게임은 끝나지 않고, 격리 후 파괴공작이 멈춰 운영이 쉬워질 뿐이다.
- 로그는 공용 로그 시스템 하나에 기록하되, 각 NPC에게는 **그 NPC가 알 수 있는 정보만 필터링**해서 준다.

## 4. 시스템 ④ — 적응형 살인마 (예방 > 반응)

### 의도
게임을 "사고가 터지면 반응하기"에서 **"애초에 공격 표면을 없애기"**로 바꾼다. 반응이 아니라 예방이 실력이 되는 순간 진짜 전략 게임이 된다.

### 규칙
살인마는 매일 무조건 움직이지 않는다. **플레이어의 실수를 조건으로만** 기회를 잡는다.

- CCTV 사각지대를 방치했을 때
- 금기를 어겨 정전·통로잠금·CCTV 단절이 일어났을 때
- 특정 방에 직원을 몰아넣어 고립 상황을 만들었을 때

살인마의 목표는 사람을 많이 죽이는 게 아니라 **코어 100% 저지 + 정체 은폐**다.

### 살인 규칙 (GAME_DESIGN 준수)
- 조건이 만족될 때만 살인이 후보 행동에 포함된다.
- 하루 최대 1회, 전체 0~2회. **관리를 잘하면 0회.**
- 고정 스크립트가 아니다. 배치·CCTV·직원 위치·금기·플레이어 개입에 따라 실제 기회가 있을 때만 시도한다.

### 역할 분리
- **Claude = 의도** (허용된 후보 행동 중 무엇을 시도할지, 어떤 말투로 거짓말할지)
- **Godot = 사실** (그 행동이 가능한가, 이동 가능한가, 살인이 성공하는가, 코어가 얼마나 깎이는가)
- Claude가 반환한 결과를 그대로 실행하지 않는다.

### 구현 순서
- 초기에는 Claude 없이 **로컬 규칙만으로** 성립시킨다. (매 프레임 API 호출 금지, 모든 NPC 주기 호출 금지)
- Claude 행동 판단은 후속 단계에서 질감으로만 얹는다.

## 5. 네 시스템이 어떻게 한 판으로 감기는가

한 판의 전략 루프는 이렇게 물린다.

1. **① 제약 만족** — 금기 때문에 완벽한 배치가 불가능 → 어딘가에 틈을 낼 수밖에 없다.
2. **② 제로섬 예산** — 감시할 전력이 부족 → 감시 못 하는 사각이 생긴다.
3. **①②의 틈이 ④의 기회를 연다** — 살인마는 그 사각·위반·고립을 노린다.
4. **④의 사보타주가 ③의 증거를 남긴다** — 로그·CCTV·진술에 모순 흔적이 찍힌다.
5. **③ 교차검증으로 격리 결정** — 확신 vs 노동력 손실의 기댓값 판단.

즉 **논리(①) → 자원(②) → 심리(④) → 추리(③)** 가 한 사이클로 맞물린다. 새 게이지 없이, 전부 기존 시스템의 충돌만으로.

## 6. 스코프 가드 (이 문서를 근거로 확장하지 말 것)

- 이 4개는 **새 시스템이 아니다.** 기존 시스템에 붙는 충돌 규칙일 뿐이다. 이를 빌미로 새 Manager/게이지/미니게임을 만들지 않는다.
- 새 수치 상태 추가 금지 (스트레스 1개 유지).
- 4개 전부 LLM 없이 성립해야 한다. Claude 의존 설계 금지.
- 모호하면 구현 전에 사용자에게 확인한다.
