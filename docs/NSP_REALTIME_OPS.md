# 야간근무지침 — REALTIME OPERATION SYSTEMS

> AI 에이전트가 **실시간 운영 계층**(밤 근무)의 구조를 구현하기 위한 문서다.
> `GAME_DESIGN.md`, `DEVELOPMENT_RULES.md`, `MANAGEMENT_STRATEGY.md`를 함께 따른다.
> 여기 있는 것은 새 게임 시스템이 아니라, 기존 자원(전력·자재·스트레스·코어)과
> 기존 3기둥(금기·코어·추리)을 **방 단위로 배선**하는 규칙이다.

## 0. 이 문서가 다루는 범위

- **시설 구조** — 작업실마다 담당 자원/기능이 다르다. 배치가 곧 자원 배분이다.
- **업무 우선도** — 방 안 업무를 드래그로 순서 지정하고 게이지로 순차 처리한다.
- **자재** — 정비실이 생산하고 코어실이 소모하는 공용 수치. 운반은 구현하지 않는다.

### 절대 원칙 (MANAGEMENT_STRATEGY 승계)
- 새 수치 상태를 만들지 않는다. 동적 직원 상태는 스트레스 1개만.
- 이 계층은 전부 LLM 없이 성립해야 한다. Claude는 대화 질감만 얹는다.
- 재미는 시스템 추가가 아니라 기존 자원/시스템의 충돌에서 나온다.

## 1. 시설 구조 — 방별 담당 자원

### 핵심 개념
작업실은 단순 공간이 아니라 **자원 하나를 쥔 거점**이다. 한 방에 인력을 몰면 다른 방이 희생된다. 이 "인력을 넣고 빼는 것 = 자원 트레이드오프"가 배치 전략의 뼈대다.

- 플레이어 자리인 **중앙 제어실은 작업실이 아니다.** 직원을 배치하지 않는다(두 모니터 화면).
- 작업실 수는 직원 수보다 많다. **작업실 8개 · 직원 6명** → 매일 한두 곳은 비워야 한다. 이 인력난이 "덜 나쁜 선택"이라는 기획 의도를 실플레이로 강제한다.

### 작업실 정의

| 작업실 | 담당 자원 / 기능 | 배치 딜레마 |
|---|---|---|
| 발전실 | 전력 공급원. 여기 업무량이 전체 전력 여유를 좌우 | 인력을 빼면 감시·환기가 약해짐 |
| 환기실 | 생존 유지. 정지 시 전 직원 스트레스 상승 | 금기가 자주 걸려 배치가 까다로움 |
| 정비실 | 자재 **생산** + 설비 고장 수리 | 코어에 쓸 자재를 여기서 벌어야 함 |
| 의무실 | 유일한 스트레스 회복처 | 보낸 직원은 그 시간 일을 못 함 |
| 감시·경비실 | CCTV·봉쇄 효율↑ (실시간 = 지금 무슨 일이) | 감시에 인력 쓰면 코어 수리가 느려짐 |
| 코어실 | 봉쇄 코어 직접 수리 (승리 조건). 자재 **소모** | 최우선인데 금기·사보타주가 제일 몰림 |
| 저장고 | 공용 자재 풀의 **저장 상한** 관리 | 여길 잠그거나 비우면 자재가 넘쳐 낭비됨 |
| 격리실 | 격리된 직원이 수용되는 곳 (근무 불가) | 오격리 시 인력 + 방 하나가 통째로 죽음 |

> 격리실은 **직원을 배치하는 방이 아니다.** 격리 명령의 대상이 이동되는 수용 공간이다. 격리는 근무표 배치가 아니라 실시간 관리자 명령으로 처리한다(한 번에 1명).

### 데이터 함의
- 방은 데이터로 정의한다. `room_id / 담당 자원 / 연결 / 전력 상태 / 잠금 상태`.
- "담당 자원"은 코드 if/else가 아니라 데이터 필드로 둔다. 방마다 어떤 자원을 만지는지 하드코딩하지 않는다.
- 프로토타입에서는 방 **업그레이드/건설을 구현하지 않는다.** "방이 자원과 연결돼 있다"까지만.

## 2. 업무 우선도 — 방 안에서 뭘 먼저, 뭘 포기할까

### 조작 흐름
1. 실시간 운영 중 방(또는 그 방 직원)을 클릭하면 **그 방의 업무 목록**이 뜬다.
2. 플레이어가 드래그로 **처리 우선순위**를 조정한다.
3. 직원은 1순위 업무부터 **게이지가 차는 방식**으로 순차 처리한다.
4. 같은 방에 두 명이 있어도 **한 업무를 동시에 처리할 수 없다** → 자연스러운 분업.

### 이게 단순 '순서 정하기'가 아니게 만드는 규칙
- **업무마다 요구 능력치가 다르다.** (수리=기술 / 위험구역 점검=담력 / 로그 확인=관찰) 능력치가 낮은 직원이 맡으면 게이지가 느리게 찬다. → "누굴 이 방에 넣나"가 우선순위와 별개의 판단이 된다.
- **업무마다 방치 결과가 다르다.** (전구 수리는 미뤄도 되지만 발전기 과열은 미루면 정전) → 우선순위 조정이 "뭘 먼저"가 아니라 **"뭘 포기할 수 있나"**의 판단이 된다.
- **금기·살인마와 연결된다.**
  - 급한 업무 2개 ↔ 금기 "해당 방 2인 금지" → 한 명만 넣어 시간을 버리거나, 2명 넣어 금기를 어기거나.
  - 살인마는 이 시스템을 악용한다: 급한 업무를 방치하거나, 우선순위를 무시하고 방을 이탈. → **"1순위가 안 찼는데 자리를 떴다"가 업무 게이지 로그에 남아 추리 단서**가 된다.

### 데이터 함의
- 업무는 데이터로 정의한다: `업무 / room / 요구 능력치 / 게이지 소요 / 방치 시 결과(사건 ID) / 우선도 기본값`.
- 프로토타입 스코프: **방당 업무 2~3개**, 그중 최소 1개는 "방치 시 사고"가 나는 업무. 방마다 5~6개씩 만들면 콘텐츠가 폭발한다.

## 3. 자재 — 공용 풀 (운반 없음)

### 핵심 결정
자재는 화면 상단 포인트로 두지 않는다(전력과 헷갈림). **정비실이 생산하고 코어실이 소모하는 공용 수치**로 둔다. **물리적 운반은 구현하지 않는다** — "정비실이 공용 통장에 입금, 코어실이 출금"으로 추상화한다.

### 규칙
- 정비실 인력이 "자재 생산" 업무를 처리하면 **시설 공용 자재 풀**이 찬다.
- 코어실 수리 게이지가 한 칸 찰 때마다 공용 풀에서 자재를 **차감**한다.
- **자재 풀이 0이면 코어 수리 게이지가 멈춘다** (수리 인력이 있어도).
- 저장고는 이 공용 풀의 **최대 저장량(상한)**을 정한다. 상한이 낮으면 자재가 금방 넘쳐 낭비된다.

### UI
- 코어실 수리 장치 옆/위에 `자재 0/100` 형태로 표시. 수리하며 줄고, 정비 생산으로 늘어난다.
- 전력(상단 포인트, 관리자 개입 자원)과 자재(방 부착 수치, 현장 소모 자원)는 **UI·성격이 분리**되어야 한다.

### 밸런싱 (미리 못 박을 것)
- **자재 생산 속도 < 코어 소모 속도.** 생산이 소모보다 빠르면 자재가 남아돌아 시스템이 무의미해진다.
- 목표 감각: "코어 수리를 계속하려면 정비실을 쉬지 않고 돌려야 한다." → 코어실 + 정비실을 동시에 굴려야 하므로 6명 인력이 더 빠듯해진다.

### 데이터 함의
- 자재 풀 총량 상한, 생산 속도, 코어 1게이지당 소모량은 전부 `Config`에서 소유한다. **매직 넘버 금지.**

## 4. 자원 요약 (역할이 겹치지 않게)

| 자원 | 성격 | 소유/표시 | 늘리는 곳 | 줄이는 곳 |
|---|---|---|---|---|
| 전력 | 관리자 개입 자원 | 상단 포인트 (최대 10) | 발전실 | 관리자 기능 사용 |
| 자재 | 현장 소모 자원 | 코어실 부착 수치 (0/상한) | 정비실 생산 | 코어 수리 |
| 스트레스 | 직원 동적 상태 | 직원별 0~100 | 금기·고립·과중 | 의무실 회복 |
| 코어 진행도 | 승리 조건 | 전역 0~100% | 코어실 수리 | 사보타주·대형 사고 |

**같은 역할의 자원/게이지를 새로 만들지 않는다.** 위 4개로 모든 운영 압박을 표현한다.

## 5. 구현 순서 (에이전트용, 실시간 운영 계층에 한정)

기존 `PROTOTYPE_PLAN`의 방/이동/근무표가 있다는 전제에서 이 계층을 얹는다.

1. **방 데이터에 '담당 자재/기능' 필드 추가** — 8개 작업실 정의, 중앙 제어실은 배치 대상에서 제외.
2. **업무 데이터 + 우선도 큐** — 방별 업무 목록, 드래그 우선순위, 게이지 순차 처리, 동일 업무 동시 처리 금지.
3. **요구 능력치 반영** — 담당 직원 능력치에 따라 게이지 속도 변화.
4. **방치 결과 연결** — 우선순위에서 밀린 업무가 방치되면 정해진 사건(정전 등)을 사건 로그로 발생.
5. **자재 공용 풀** — 정비 생산 → 풀 증가, 코어 수리 → 풀 감소, 0이면 수리 정지. 저장고가 상한 결정.
6. **격리실 연결** — 격리 명령 시 대상 직원을 격리실로 이동시키고 근무에서 제외.
7. **업무 게이지 로그** — "1순위 미완 상태 이탈" 같은 이벤트를 공용 로그에 남겨 추리 단서로 사용.

각 단계는 데이터 주도로 구현하고, 판정(게이지 완료·자재 차감·방치 사건 발생)은 전부 Godot가 소유한다. Claude에 게임 상태를 직접 넘기거나 수정하게 하지 않는다.

## 6. 이 문서 기준 하지 말 것

- 자재 **운반** 캐릭터/동선/시간 구현 (물류 시뮬화 금지).
- 방 **건설/업그레이드** 프로토타입 구현.
- 방당 업무를 5개 이상으로 늘리기.
- 전력·자재·스트레스·코어 외 **새 자원/게이지 추가**.
- 격리실을 "배치하는 방"으로 만들기 (수용 공간일 뿐).
- 모호하면 구현 전에 사용자에게 확인한다.
