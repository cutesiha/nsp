# 야간근무지침 — REALTIME OPERATION SYSTEMS (REVISED)

> 현재 3D 중앙제어실 버전의 실시간 운영 구조를 정의한다.
>
> 핵심은 시스템 수를 늘리는 것이 아니라
> **직원 배치 / 전력 / 정보 / 사고 / 금기 / 추리**가 서로 충돌하도록 만드는 것이다.
>
> 플레이어가 완벽한 운영을 할 수 없고,
> 매 순간 **무엇을 포기할지 선택하게 하는 것**이 목표다.

---

# 0. 현재 운영 계층의 핵심 조작

실시간 근무 중 관리자가 직접 사용하는 핵심 기능:

1. 직원 재배치
2. CCTV 방 선택
3. 전력 배분
4. 전화/호출
5. 격리

삭제 유지:
- 업무 우선도 큐
- 수동 구역 봉쇄
- 복잡한 별도 작업 메뉴

플레이어의 우선순위 판단은 업무 순서를 직접 정렬하는 것이 아니라
**어느 직원을 어느 방에서 빼서 어디에 보낼지**로 표현한다.

---

# 1. 시설 구조

작업실은 각각 하나의 중요한 시설 기능을 담당한다.

작업실 8개 / 직원 6명이므로 처음부터 모든 방을 커버할 수 없다.

근무 시작 전:
**코어실에는 반드시 직원 1명 이상을 배치해야 한다.**

| 작업실 | 핵심 기능 | 비워두거나 사고 시 손실 |
|---|---|---|
| 발전실 | 전력 공급 | LIGHTING / CCTV / SENSOR 유지 어려움 |
| 환기실 | 시설 환기 / 스트레스 억제 | 전 직원 스트레스 상승 |
| 정비실 | 자재 생산 / 설비 수리 | 자재 공급 중단, 코어 수리 지연 |
| 의무실 | 직원 스트레스 회복 | 회복하는 동안 업무 인력 감소 |
| 경비실 | 감시 설비 안정화 / 파괴공작 억제 | CCTV 사고 위험, 감시 보너스 상실 |
| 코어실 | 코어 직접 복구 | 승리 조건 진행 정지 |
| 저장고 | 자재 저장 상한 | 자재 초과분 낭비 가능 |
| 격리실 | 의심 직원 수용 | 일반 배치 공간이 아님 |

격리실은 근무표에서 일반 직원이 배치되는 방이 아니다.

---

# 2. 직원 배치 / 재배치

## 근무 시작 전
코어실 최소 1명 필수.

초기 배치는:
**사고 발생 전의 유리한 시작 진형**을 정하는 단계다.

## 실시간 재배치
재배치는 가능하지만 순간이동은 아니다.

- 실제 이동 시간 존재
- 이동 중 업무 불가
- 기존 방에서 빠지는 순간 그 방 효율 저하 가능
- 요구 능력치에 맞는 직원일수록 업무 처리 속도 증가

따라서:
> 누구를 빼면 어떤 방이 비고,
> 그 직원이 도착하기 전까지 무엇을 포기해야 하는가
를 고민하게 한다.

---

# 3. 업무 처리 — 업무 우선도 폐기

기존 `업무 우선도 큐 / 드래그 정렬`은 사용하지 않는다.

- 작업실에 활성 업무가 발생한다.
- 해당 방 직원이 업무를 처리한다.
- 요구 능력치와 직원 능력치에 따라 속도가 달라진다.
- 일정 시간 방치하면 TaskDef에 연결된 시설 사고 발생.
- 중요한 사고 업무는 SENSOR가 사전 경고.

UI:
- 방 노드
- 현재 업무
- 남은 시간
- 배치 직원
- 사고 위험

기존 우선도 버튼/큐/숫자 UI는 제거한다.

---

# 4. 전력 시스템 — 핵심 운영 자원

전력은 더 이상 최대 10 포인트를 소비하는 방식이 아니다.

현재 프로토타입 기준:
**POWER CAPACITY 최대 3칸**

세 기능이 각 1칸을 사용한다.

- LIGHTING
- CCTV
- SENSOR

정상:
`POWER 3 / 3`
세 기능 모두 ON.

발전실 사고/금기로 용량이 2 또는 1로 떨어지면
플레이어가 직접 무엇을 끌지 선택한다.

전력 조작은 3D 책상의 작은 물리 패널로 처리한다.
큰 전체화면 메뉴는 사용하지 않는다.

---

# 5. LIGHTING — WHERE

LIGHTING의 게임적 역할:
**직원 실시간 위치 확인**

## ON
- Monitor 01 직원 아이콘 표시
- 이동 중 동선/위치 확인

## OFF
- 일반 작업실 직원 아이콘 소실
- 실제 직원은 그대로 존재
- 관리자가 위치를 모르는 상태

## 비상 조명
DAY 1 기준:
- 코어실
- 경비실

두 방은 LIGHTING OFF여도 직원 아이콘 유지.

LIGHTING = **WHERE — 누가 어디에 있는가**

---

# 6. CCTV — WHAT

오른쪽 Monitor 02 담당.

## ON
- 선택 방 실제 상황 확인
- 직원이 무엇을 하는지 확인
- 사고/사보타주 흔적/이상현상 확인

## OFF
`NO SIGNAL`
`CCTV POWER OFF`

CCTV = **WHAT — 그곳에서 무엇을 하고 있는가**

---

# 7. SENSOR — WHEN / WHAT NEXT

SENSOR는 책상 위 ALERT TERMINAL과 연결.

## ON
사전 제공:
- 시설 사고 종류
- 사고 방
- 남은 시간
- 금기 위반 카운트다운
- 코어 자재 부족

예:
`⚠ GENERATOR OVERHEAT`
`POWER ROOM`
`00:20`

## OFF
- 사전 예측/카운트다운 없음
- 실제 사고 발생 순간 최소 고장 경보만 표시

SENSOR = **WHEN / WHAT NEXT — 다음에 무엇이 터질 것인가**

---

# 8. 전력 선택의 딜레마

전력 용량 2일 때:

## LIGHTING + CCTV
- 위치 확인 가능
- 행동 확인 가능
- 사고 예측 불가

## LIGHTING + SENSOR
- 위치 확인 가능
- 사고 예측 가능
- 직접 감시 불가

## CCTV + SENSOR
- 행동 확인 가능
- 사고 예측 가능
- 전체 직원 위치 추적 불가

핵심:
**완벽한 선택은 없다.**

전력은 수치 관리가 아니라
**어떤 종류의 정보를 포기할지 선택하는 시스템**이다.

---

# 9. ALERT TERMINAL

책상 위 작은 산업용 경고 단말기.

평상시:
`SYSTEM NORMAL`
`NO ACTIVE ALERTS`

사고:
`⚠ GENERATOR OVERHEAT`
`00:20`

금기:
`⚠ PROTOCOL VIOLATION`
`POWER ROOM`
`00:08`

자재:
`⚠ CORE MATERIAL LOW`
`3 REMAINING`

시청각 피드백:
- WARNING: 주황등 + 느린 경고음
- DANGER: 점멸/경고음 빨라짐
- FAILURE: 빨간등 + 강한 경고음 + Monitor 01 해당 방 붉은 점멸

큰 중앙 Popup은 사용하지 않는다.

---

# 10. 시설 사고와 전력/운영 연결

사고는 `고장 → 수리`로 끝나지 않는다.

## 발전실
- 전력 용량 감소/완전 정전
- LIGHTING/CCTV/SENSOR 상실

## 환기실
- 환기 정지
- 전 직원 스트레스 지속 상승

## 정비실
- 자재 생산 정지
- 코어 자재 공급 악화

## 경비실
- CCTV 장비 자체 OFFLINE
- 전력을 줘도 수리 전까지 사용 불가

모든 사고는:
- 실제 소리
- CCTV 시각 변화
- Monitor 01 상태 변화
- 실제 기능 손실

을 동반한다.

---

# 11. 금기

금기는 제한문 + 작은 수치 페널티가 아니다.

금기 위반 시:
- 강한 시청각 이상현상
- 즉각 이해 가능한 운영 손실
- 일정 시간 지속되는 위험

DAY 1:
**발전실 2인 이상 금지** 고정.

발전 사고가 급하면 2명을 보내고 싶지만,
금기를 어기면 전력망 전체가 크게 흔들린다.

상세는 `NSP_DAY1_EVENTS_REVISED.md`.

---

# 12. 자재

기존 공용 풀 유지.

- 정비실 생산
- 코어실 소비
- 자재 0이면 코어 복구 정지
- 저장고가 최대 보유량에 영향
- 물리적 운반 구현 안 함

역할 구분:
- 전력 = 정보 시스템 선택
- 자재 = 코어 복구 지속 여부

---

# 13. 스트레스

기존 직원별 스트레스 유지.

상승:
- 환기 사고
- 일부 금기 이상현상
- 위험 상황
- 기타 기존 조건

회복:
- 의무실

새 정신력/공포도/피로도 게이지는 추가하지 않는다.

---

# 14. 코어

코어 복구율 100%가 승리 조건.

- 근무 시작 전 코어실 최소 1명 필수
- 코어실 직원 0명이면 복구 정지
- 자재 0이면 복구 정지
- 사보타주/대형 사고로 지연 가능

따라서:
코어에 좋은 직원을 오래 둘수록 승리에 유리하지만
다른 시설 대응 인력이 부족해진다.

---

# 15. 경비실

기존 `SurveillanceSaboteurChanceMultiplier` 같은
파괴공작/살인 확률 감소 보너스는 유지 가능.

단:
- CCTV 전력 상태
- CCTV 설비 상태
- 경비실 인력 보너스

는 서로 별개 조건이다.

---

# 16. 격리

- 의심 직원 1명 수용
- 격리 중 근무 불가
- 진범 격리 → 이후 사보타주 정지
- 오격리 → 인력 손실 + 진범 계속 활동

수동 구역 봉쇄 기능은 되살리지 않는다.

---

# 17. 실시간 운영의 핵심 연쇄

`업무 발생`
→ `SENSOR 경고`
→ `누굴 보낼지 판단`
→ `기존 방 인력 이탈`
→ `다른 업무 효율 감소`
→ `사고 예방 또는 발생`
→ `전력/환기/자재/CCTV 변화`
→ `감시 공백`
→ `파괴공작 가능`
→ `로그/CCTV/위치 정보로 추리`

플레이어가 머리를 쓰는 지점은
버튼 수가 아니라 **이 연쇄에서 무엇을 포기하는가**다.

# 20. 핵심 자원 요약

| 요소 | 역할 | 핵심 선택 |
|---|---|---|
| 전력 | 정보 기능 유지 | LIGHTING/CCTV/SENSOR 중 무엇을 유지할지 |
| 자재 | 코어 복구 자원 | 정비실 인력을 계속 유지할지 |
| 스트레스 | 직원 상태 | 의무실에 보내 업무 인력을 포기할지 |
| 코어 복구율 | 승리 조건 | 코어에 인력을 얼마나 투자할지 |
| 직원 | 가장 중요한 제한 자원 | 누구를 어디서 빼고 어디로 보낼지 |

핵심:
**직원이 가장 중요한 자원이고,
전력은 정보의 범위를 결정하는 두 번째 핵심 자원이다.**

# 22. 검증 질문

1. 시작 배치에서 실제로 고민하는가?
2. 실시간 재배치에 기회비용이 있는가?
3. 발전 사고 후 전력 선택을 실제로 고민하는가?
4. LIGHTING/CCTV/SENSOR가 서로 다른 정보를 주는가?
5. 사고가 작은 텍스트가 아니라 공간에서 체감되는가?
6. 금기를 어기는 것이 진짜 무서운 선택인가?
7. 정보가 끊기는 순간 파괴공작 위험이 자연스럽게 커지는가?
8. 살인 사건의 정보가 너무 완벽하지도, 완전히 랜덤하지도 않은가?
9. 업무 우선도 없이 직원 재배치만으로 운영 판단이 생기는가?
10. `완벽한 정답은 없다`는 기획 의도가 실제 플레이에서 느껴지는가?
