# 1. 이번 개편의 핵심 목적

현재 게임은 시스템 자체는 DAY5까지 정상적으로 굴러가지만, 초반 튜토리얼의 정보 전달 방식이 지나치게 GUIDE-0 중심입니다.

현재 문제:

- GUIDE-0가 작업실/기능을 하나씩 설명하는 시간이 길다.
- 플레이어가 시스템을 "상황"으로 이해하기보다 텍스트를 읽고 외워야 한다.
- 작업실별 규칙이 많아 한 번 읽고 기억하기 어렵다.
- 게임을 이미 아는 개발자 입장에서도 긴 설명이 잘 읽히지 않는다.
- 처음 플레이하는 사람은 설명을 들었는데도 왜 그렇게 해야 하는지 이해하지 못할 가능성이 높다.
- 직원 6명의 성격/관계가 게임의 중요한 추리 요소인데 DAY0에서는 충분히 살아나지 않는다.
- 이미 잘 만들어 놓은 3D CCTV 캐릭터 대화 시스템과 2D 스탠딩 일러를 초반에 충분히 활용하지 못한다.

이번 개편의 목표:

> **"GUIDE-0가 게임 규칙을 강의한다"**
>
> 에서
>
> **"플레이어가 상황을 먼저 경험하고, 직원이 인간적인 반응을 보이며, GUIDE-0는 필요한 규칙만 짧게 정리한다"**
>
> 로 변경.

# 2. 절대로 깨뜨리면 안 되는 핵심 세계관 규칙

## 2.1 관리자와 직원의 직접 대화 수단은 전화기

이 원칙은 반드시 유지합니다.

직원 → 관리자 직접 통신용 별도 무전기/영상통화/COMM 시스템을 새로 만들지 마세요.

관리자와 직원이 실시간으로 직접 대화하려면:

`직원 전화 발신 → 전화벨 → 플레이어가 전화기를 듦 → 통화`

또는

`플레이어가 직원을 선택해 전화 발신`

이라는 기존 전화 구조를 사용합니다.

금지:

- 직원이 갑자기 화면에 2D 일러로 등장해 관리자에게 직접 말함
- 별도의 영상 통신 UI 추가
- "COMMUNICATION CONNECTED" 같은 새 설정을 만들어 전화기의 존재 의미를 약화

# 3. 3D와 2D 스탠딩의 역할을 명확히 분리

NSP는 기본적으로 3D 관제 게임입니다.

2D 스탠딩 일러는 **새로운 세계관 장치가 아니라 게임의 연출 언어**로 사용합니다.

## 3.1 실시간 근무 중 일반 직원 행동

사용:

- 기존 3D CCTV 캐릭터
- 기존 RoomWorkVisualController
- 기존 직원 간 자동 대화
- 관계도 기반 대사
- 기존 캐릭터별 반응/애니메이션

2D 스탠딩을 띄우지 않습니다.

이 영역은 "직원들이 실제 시설 안에서 살아 움직인다"는 생활감을 담당합니다.

## 3.2 직원 ↔ 직원의 자연발생 대화

현재 이미 구현된 시스템을 유지합니다.

같은 방에 여러 직원이 있을 때:

- 관계도
- 성격
- 상황

에 따라 3D 캐릭터끼리 대화하는 구조를 그대로 사용합니다.

이 대화는 메인 스토리 대본이 아니라 **생활감/관계성** 담당입니다.

## 3.3 관리자 ↔ 직원 직접 대화

반드시 전화기 사용.

전화기를 든 순간:

- 기존 PhoneCallHud
- 직원 2D StandingImage
- EmployeeMouthAnimator
- 표정/입 모양 리소스

를 적극 활용합니다.

2D 스탠딩은 "영상 통화"가 아닙니다.

세계관 안에서는 음성 전화지만,
게임 연출상 상대 직원의 감정과 캐릭터성을 보여주기 위해 스탠딩을 표시합니다.

## 3.4 메인 스토리에서 직원끼리 대화할 때

별도 풀스크린 Visual Novel Scene으로 화면을 완전히 교체하지 않는 것을 우선합니다.

권장:

`실제 3D CCTV/휴게실/작업실 화면`
+
`말하는 직원 2D Standing Cut-in`
+
`대사 자막`

형식.

즉:

- 공간/사건은 3D
- 감정/표정 강조는 2D
- 대사는 작성된 스토리 스크립트

로 나눕니다.

# 7. GUIDE-0의 역할 재정의

기존:
`튜토리얼 교사`

개편:
`시설 관제 보조 AI`

GUIDE-0는 다음만 말합니다.

- 현재 무엇이 문제인지
- 그 문제를 해결하려면 무엇이 필요한지
- 처음 보는 규칙의 핵심 1개

## 7.1 GUIDE 대사 길이

기본:

1~2문장.

한 메시지 안에 3가지 이상의 시스템 규칙을 넣지 마세요.

좋은 예:

> "자재가 부족합니다. 정비실에 직원을 배치하면 자재를 생산할 수 있습니다."

나쁜 예:

> "정비실에서는 코어 복구에 필요한 자재를 생산하며 저장고에 인원을 배치할 경우 최대 보관량이 증가하고..."

## 7.2 플레이어가 이미 화면에서 볼 수 있는 것을 GUIDE가 다시 읽어주지 않음

UI:

`필요 인원 2명`

이 보인다면 GUIDE가:

> "이 작업에는 두 명이 필요합니다."

라고 반드시 다시 읽을 필요 없습니다.

필요할 때만:

> "큰 설비는 혼자 수리할 수 없습니다."

정도로 맥락만 줍니다.

# 9. DAY0의 목적

DAY0은 모든 시스템을 100% 설명하는 날이 아닙니다.

DAY0의 목적:

> **"NSP의 기본 문법을 이해하게 한다."**

DAY0이 끝날 때 플레이어가 이해해야 할 것:

1. 직원은 작업실에 배치한다.
2. 필요하면 실시간으로 다시 배치한다.
3. 봉쇄 코어 복구가 장기 목표다.
4. 코어 복구에는 자재가 필요하다.
5. 작업실마다 다른 기능이 있다.
6. 경고를 방치하면 사고가 된다.
7. 사고 대응에는 직원을 보내야 한다.
8. CCTV로 시설과 직원을 확인한다.
9. 전화기로 직원과 직접 대화한다.
10. 근무 후 휴게시간에서 기록/증언을 확인한다.

DAY0에서 반드시 완전히 설명하지 않아도 되는 것:

- 방해공작 전체 구조
- 격리 리스크 전체
- 살인 위험
- 환기실 세부 스트레스 수치
- 의무실 장기 전략
- 고급 Evidence 추궁
- 모든 작업실 인원별 효율 수치

이들은 DAY1~2의 실전 상황과 PAD 도움말로 분산합니다.

GUIDE:

> "좋습니다. 남은 직원은 직접 배치해 보십시오."

끝.

# 11. DAY0 직원 사용 원칙

직원을 시스템 설명용 마네킹처럼 만들지 마세요.

직원은:

- 상황을 먼저 감지하거나
- 자신이 느낀 문제를 전화로 보고하거나
- 다른 직원과 3D로 짧게 반응

하게 합니다.

GUIDE는 시설 규칙만 짧게 정리.

# 12. 전화와 튜토리얼을 연결하는 방법

직원이 관리자에게 직접 말을 해야 하는 중요한 상황은
반드시 전화기를 사용합니다.

예:

자재 부족 발생.

전화벨.

플레이어가 실제 전화기를 듦.

토끼 StandingImage + mouth animation:

> "관리자님, 이쪽 작업이 멈췄어요. 자재가 부족한 것 같은데요?"

GUIDE-0:

> "봉쇄 코어 복구에는 자재가 필요합니다."
>
> "정비실에서 자재를 생산할 수 있습니다."

이후 행동.

이 구조로 인해:

- 전화기의 존재 이유 강화
- 2D 스탠딩 사용
- 캐릭터 성격 노출
- 시스템 설명
- 조작 체험

을 한 번에 해결합니다.

---

# 13. 모든 튜토리얼을 전화로 만들지는 말 것

전화가 남발되면 또 느려집니다.

전화는:

- 직원이 직접 발견한 상황
- 인간적인 반응이 중요한 상황
- 스탠딩 일러를 보여줄 가치가 있는 순간

에만 사용.

객관적인 시스템 상태는 GUIDE/System Notice/UI가 담당합니다.

# 14. 직원 6명의 튜토리얼 역할

아래는 "누가 어떤 종류의 시스템을 인간적인 반응으로 받아주면 좋은가"에 대한 기본 방향입니다.

실제 DAY0 인원 구성에 맞춰 필요한 캐릭터만 사용하고,
DAY1~2에서 나머지를 활용해도 됩니다.

## 토끼

성격:

- 활발
- 호기심
- 반응 큼

정비실 Highlight.

자재 숫자 증가.

코어 다시 움직임.

UI:

`자재 10/10`
`추가 생산분 폐기`

GUIDE:

> "저장고에 인력을 두면 더 많은 자재를 보관할 수 있습니다."

저장고 Highlight.

끝.

# 23. 휴게시간 설명

필수 이해:

- 전화/대화 기록 = 직원이 실제로 말한 내용
- CCTV Evidence = 플레이어가 직접 관측한 것
- 직원 인터뷰 = 기록과 말을 비교하는 단계
- 자료 두 개를 함께 제시하면 모순을 확인할 수 있음

모든 고급 기능을 한꺼번에 시키지 않습니다.

DAY0:

1. 직원 한 명 선택
2. 전화 연결
3. 기본 질문 한 번
4. 기록 하나 선택
5. 관련 질문 한 번

정도.

# 24. 2D Story Cut-in 공통 시스템

이 시스템은 풀스크린 VN Scene이 아닙니다.

기본 구성:

`실제 3D 시설/CCTV 배경`
+
`2D Standing Cut-in`
+
`Speaker Name`
+
`Dialogue Text`

## 24.1 화면 규칙

- 한 번에 기본 1명 표시
- 2인 대화는 최대 2명
- 3명 이상이면 말하는 인물 중심으로 교체
- 스탠딩이 3D 공간 전체를 가리지 않음
- 기존 UI/CRT 톤과 통일
- 갑자기 밝고 화려한 VN 프레임 금지

## 24.2 기존 EmployeeMouthAnimator 재사용

대사 타이핑 중:

- small mouth
- big mouth
- closed mouth

프레임을 현재 구현처럼 사용.

대사 종료 시 closed mouth.

## 24.3 표정

현재 캐릭터별:

- 기본
- smile
- bad

등 리소스가 있다면 Story Script에서 표정 지정 가능하게 합니다.

예:

```text
speaker: cat
expression: bad
text: ...
```

표정 리소스가 없는 경우 기존 StandingImage fallback.

# 40. 최종 성공 기준

새 플레이어가 DAY0~DAY2를 경험한 후:

## 시스템

- "코어 복구가 목표다."
- "자재가 필요하다."
- "방마다 역할이 있다."
- "직원을 옮겨 문제를 대응한다."
- "CCTV를 봐야 한다."
- "전화로 직원과 얘기한다."
- "근무 끝나면 기록과 증언을 비교한다."

를 자연스럽게 이해.

## 캐릭터

- 6명이 서로 다른 사람처럼 느껴짐.
- 직원들의 관계가 존재한다는 걸 초반부터 느낌.
- Standing Illustration이 실제 게임 안에서 자주 의미 있게 사용됨.

## 연출

- 갑자기 다른 Visual Novel 게임으로 바뀐 느낌 없음.
- 3D와 2D가 하나의 관제 화면 연출처럼 이어짐.
- 전화기의 존재 의미 유지.

## 튜토리얼

- 긴 GUIDE 강의 감소.
- 상황 → 반응 → 짧은 설명 → 행동 구조.
- 플레이어가 "설명은 들었는데 이해 못했다"는 불쾌감을 최소화.
