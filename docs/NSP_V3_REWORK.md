# NSP V3 전체 개편안
## Branch: `v3`

---

# 0. V3 개편 목표

V3의 가장 큰 목표는 **게임의 핵심을 다시 단순하게 만드는 것**이다.

기존 버전은 처음부터 다음 시스템이 동시에 등장했다.

- 직원 능력치
- 직원 성격
- 스트레스
- 금기
- 작업실 사고
- 작업실별 다른 규칙
- 전력
- CCTV
- 센서
- 전화
- 시설 로그
- 인터뷰
- 방해자
- 코어 복구

이 때문에 처음 플레이하는 사람이

> “내가 지금 뭘 해야 하는지 모르겠다.”

고 느끼는 문제가 발생했다.

V3에서는 먼저 가장 기본적인 추리 재미만 이해시키고,
플레이가 진행될수록 새로운 시스템을 하나씩 추가한다.

---

# 1. 게임 장르와 핵심 재미 재정의

기존:

> 공포 경영 시뮬레이션

V3:

> **공포 추리 게임**

내부 개발 방향을 이해하기 위한 한 줄 설명:

> **“어몽어스 / 구스구스덕을 관리자 입장에서 플레이하는 게임.”**

외부 소개용 문장:

> **직원들의 시설 로그와 증언을 비교해 내부의 방해자를 찾아내는 실시간 공포 추리 게임.**

핵심 재미는 하나로 고정한다.

> **매일 시설 로그와 대화 기록을 비교해 방해자를 추리하고, 동시에 코어를 복구하며 스릴과 성취감을 느끼는 것.**

모든 운영 시스템은 이 핵심 재미를 보조하는 방향으로 사용한다.

---

# 2. 난이도 상승 구조

처음부터 모든 시스템을 제공하지 않는다.

기본 구조:

> **프롤로그 → DAY0 튜토리얼 → DAY1~DAY5 → 2사이클 시작 → 이후 시스템 추가**

플레이어가 기본 규칙을 이해한 뒤,
새로운 시스템을 하나씩 해금한다.

예시:

### 초반
- 직원 배치
- 작업실 운영
- 작업실 사고
- 시설 로그
- 대화 기록
- 방해자 추리
- 코어 복구

### 이후
- 스트레스 추가

### 더 이후
- 금기 추가

### 이후 난이도
- 복합 사고
- 이상현상
- 새로운 작업실
- 새로운 방해공작
- 추가 정보 제한

즉,

> **난이도를 없애는 것이 아니라, 플레이어가 배울 수 있는 순서로 재배치한다.**

---

# [현재 우선 구현 범위]

현재 에이전트에게 실제로 작업시킬 내용은 **1번과 2번만**이다.

- 1. 초반 시스템 단순화
- 2. 오늘의 기분상태 추가

3~5번은 아직 구현하지 않고 기획 방향만 유지한다.

---

# 3. [구현 1] 초반 시스템 단순화

DAY0와 DAY1에서는 다음 요소를 제거 또는 비활성화한다.

- 직원 능력치
  - 기술
  - 담력
  - 관찰
- 스트레스 수치
- 금기
- 환기실
- 의무실

## 중요한 원칙

이 시스템들을 프로젝트 전체에서 완전히 삭제하는 것은 아니다.

향후 난이도 상승 과정에서 다시 사용할 수 있으므로,
가능하면 코드를 날리기보다:

- UI에서 숨기기
- DAY1에서 비활성화
- 배치 대상에서 제외
- 로직 실행을 막기

방식으로 처리한다.

### DAY1에서 남겨야 하는 기본 사이클

> **직원 배치**
> → **작업실 운영**
> → **사고 또는 이상 발생**
> → **로그 / 대화 단서 확보**
> → **방해자 추리**
> → **코어 복구**

DAY1의 목적은
복잡한 운영을 버티는 것이 아니라
“이 게임이 방해자를 찾는 게임이다”를 이해시키는 것이다.

---

# 4. [구현 2] 오늘의 기분상태

기존 직원 능력치를 제거하고,
각 직원에게 **오늘의 기분상태**를 하나씩 제공한다.

## 목적

기분상태는 능력치처럼 정답을 주는 정보가 아니다.

플레이어가 근무 시작 전에

> “오늘 누가 좀 이상해 보이는가?”

를 생각하게 만드는 **추리용 사전 단서**다.

예:

- 행복함
- 괜찮음
- 그냥 그럼
- 짜증남
- 불안함
- 잘 모르겠음

플레이어는 이 정보를 보고 직원을 배치하고,
근무가 끝난 뒤 실제 행동과 비교한다.

예:

> “고양이가 오늘 짜증난다고 했는데 실제로 계속 이상행동을 했다.”
>
> “해파리가 불안하다고 했지만 아무 문제도 없었다.”

즉,

> **예측 → 플레이 → 확인**

구조를 만든다.

---

# 5. 오늘의 기분상태 핵심 규칙

기분상태는 완전 랜덤으로 정하지 않는다.

기본적으로 다음 요소만 사용한다.

1. 캐릭터의 기본 성격
2. 이전 DAY에서 실제로 겪은 사건
3. 사고 / 이상현상 / 사망 / 목격 등의 경험

방해자라고 해서 자동으로 부정적인 기분이 나오게 만들지 않는다.

예:

잘못된 방식:

> 방해자 = 불안함 확률 증가

이 방식은 플레이어가 몇 판 후
기분상태만 보고 범인을 찍을 수 있게 만든다.

대신:

> 같은 사건을 겪어도 캐릭터마다 표현 방식이 다르다.

정도로 처리한다.

# 8. 기분상태 선정 방식

기본 규칙은 단순하게 유지한다.

## 사건이 없는 경우

> 캐릭터 성격에 맞는 무난한 상태 중 하나 선택

## 가벼운 사건을 겪은 경우

예:
- 작은 작업실 사고
- 이상한 소리
- 수상한 직원 목격
- 반복적인 재배치

가능한 표현:
- 찝찝함
- 신경 쓰임
- 예민함
- 걱정됨
- 피곤함
- 불편함

## 강한 사건을 겪은 경우

예:
- 살인 목격
- 시신 발견
- 심각한 이상현상
- 공격 피해
- 동료 사망

가능한 표현:
- 충격받음
- 무서움
- 혼란스러움
- 잠을 못 잤음
- 화남
- 죄책감이 듦
- 계속 신경 쓰임

중요:

> 이 시스템을 복잡한 심리 시뮬레이션으로 만들지 않는다.

기분상태는 어디까지나
플레이어에게 주는 간단한 추리 단서다.

---

# 9. 모호한 표현

다음과 같은 표현은 허용한다.

- 미정
- 잘 모르겠음
- 별생각 없음
- 말로 설명하기 어려움
- 그냥 그럼

다만 모든 직원이 이런 표현만 사용하면 단서 의미가 없어지므로,
한 DAY에 많아도 1~2명 정도만 사용한다.

---

# 10. 기분상태와 인터뷰 연결

기분상태는 근무 배치 화면에서 끝나는 정보가 아니다.

휴게시간 인터뷰에서 다시 사용할 수 있다.

예:

오늘의 기분:
> 짜증남

질문:
> “오늘 기분이 좋지 않다고 적으셨는데, 이유가 있습니까?”

오늘의 기분:
> 기분 좋음

질문:
> “오늘 기분이 좋다고 적으셨는데 특별한 일이 있었습니까?”

오늘의 기분:
> 잘 모르겠음

질문:
> “기분을 ‘잘 모르겠음’이라고 적은 이유가 있습니까?”

답변은 기존 로컬 대화 시스템을 사용한다.

실제 게임에서 발생한 사건,
해당 직원이 실제로 알고 있는 정보,
캐릭터 성격을 기반으로 답한다.

없는 사건을 새로 만들어내면 안 된다.

---

# 11. 근무 배치 UI

기존 능력치 영역은 제거한다.

직원 카드에는 우선 다음 정보만 보여준다.

- 직원 코드네임
- 캐릭터 이미지 / 아이콘
- 오늘의 기분상태

예:

> 고양이  
> 오늘의 기분: **짜증남**

> 까마귀  
> 오늘의 기분: **평소와 비슷함**

기분상태는 근무 배치 판단에 사용하는 정보이므로
작은 보조 텍스트가 아니라 눈에 잘 보이게 배치한다.

---

# 12. 구현 시 주의사항

1. 기분상태를 완전 랜덤으로 만들지 않는다.
2. 방해자 여부만으로 기분을 결정하지 않는다.
3. 기분만 보고 범인을 확정할 수 없어야 한다.
4. DAY1에는 대부분 무난한 기분을 사용한다.
5. 강한 사건이 있을 때만 극단적인 표현이 자주 등장한다.
6. 모호한 표현은 하루 1~2명 정도로 제한한다.
7. 동일 직원이 매일 같은 표현만 반복하지 않게 한다.
8. 캐릭터 성격과 너무 어긋나는 표현은 피한다.
9. 기분상태는 직원 본인이 작성한 자기보고이며, 거짓말하지 않는다.
10. 다만 감정을 약하게 표현하거나 모호하게 표현하는 것은 가능하다.
11. 기존 대화 시스템에서 사용할 수 있도록 직원별 DailyMood를 저장한다.
12. 현재 단계에서는 복잡한 감정 수치, 호감도, 정신력 등의 추가 시스템을 만들지 않는다.

# [향후 개편 - 현재 구현하지 않음]

# 13. 프롤로그 + DAY0 튜토리얼

게임 시작 시 다음 구조를 추가한다.

> 프롤로그
> → GUIDE-0 등장
> → 신규 관리자 설명
> → DAY0 튜토리얼
> → DAY1 시작

GUIDE-0는:

- 세계관 설명
- 시설 설명
- 신규 관리자 교육
- 조작 안내
- 시스템 해금 안내

를 담당한다.

튜토리얼은 설명창만 읽는 방식이 아니라
플레이어가 직접 행동하며 배우게 한다.

예:

> GUIDE-0 설명
> → 직접 근무표 열기
> → 직원 배치
> → 작업실 확인
> → 사고 경고 확인
> → 직원 이동
> → 시설 로그 확인
> → 인터뷰

---

# 14. 시스템 해금 방식

향후 새로운 시스템이 등장할 때
GUIDE-0가 다시 등장해 짧게 설명할 수 있다.

예:

> “새로운 운영 규정이 추가되었습니다.”

- 스트레스 시스템 해금
- 금기 시스템 해금
- 새로운 작업실
- 새로운 이상현상

즉 DAY0에서 모든 것을 설명하지 않는다.

새로운 요소는
실제로 처음 등장하는 시점에 설명한다.

---

# 15. 조작 방식 개선

현재 숫자키 1~4는 각 기기를 확대하는 기능이다.

이 기능을 유지할지 제거할지는 아직 결정하지 않는다.

작업실 선택은 우선:

- 마우스 클릭 가능
- 향후 단축키 추가 검토

정도로 둔다.

UI 개편이 끝나기 전에 키 배치를 먼저 확정하지 않는다.

---

# 16. 밸런싱

현재 단계에서는 수치 밸런싱을 최우선으로 하지 않는다.

먼저:

1. 시스템 단순화
2. 기분상태
3. DAY0

를 완성한 뒤 플레이테스트를 진행한다.

그 이후:

- 작업실 고장 시간
- 수리 시간
- 작업자 수
- 코어 복구율
- 방해공작 빈도
- 하루 목표치
- 격리로 인한 인원 감소
- DAY별 난이도

를 다시 조정한다.

현재 존재하는 수리시간/고장시간 수치는
아직 최종 확정값으로 취급하지 않는다.

---

# 17. V3의 최종 기준

V3에서 플레이어가 DAY1을 처음 플레이했을 때
최소한 다음 질문에는 스스로 답할 수 있어야 한다.

> 나는 무엇을 해야 하는가?

> 누구를 의심해야 하는가?

> 어떤 정보를 봐야 하는가?

> 왜 사고가 발생했는가?

> 근무가 끝난 뒤 무엇을 확인해야 하는가?

이 다섯 가지가 이해된 뒤에
스트레스, 금기, 이상현상 같은 추가 난이도를 제공한다.
