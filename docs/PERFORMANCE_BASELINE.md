# NSP 성능 기준선 — PHASE 1

측정일 2026-10-12. 이 문서는 **실제로 돌려서 잰 값만** 담는다. 재지 못한 것은
"측정 불가" 로 적는다.

기기를 빌려 재지 않아도 되는 대신, 여기 숫자는 **이 기계 기준**이다.

| 파일 | 하는 일 |

**측정 오버헤드는 구간당 0.2~0.5 ms**(4초 구간 전체 합)로, 결과를 흔들지 않는다.

### 측정 불가 항목

- **GPU 프레임 시간** — Godot 4.7 의 `Performance` 모니터에 없다. 대신 "무엇을 끄면
  몇 ms 가 줄어드는가" 로 간접 확인했다(아래 B 표).
- **Export 릴리스 빌드** — 이번엔 디버그 빌드로만 측정했다. 다만 C# 로직이 전체의
  2% 미만이라(아래) 릴리스로 바꿔도 그림이 크게 달라지지 않을 것으로 본다.

## D. 점프스케어 — 첫 등장과 두 번째의 차이

| | 1회차 | 2회차 | 차이 |
|---|---|---|---|
| **호출 → 화면 표시** | **142.29 ms** | **31.33 ms** | **−111 ms** |
| `MonsterActor.Use` (모델 로드) | **88.77 ms** | 0.001 ms | −88.8 ms |
| 최악 프레임 (V-Sync 켬) | 136.01 ms | 50.00 ms | −86 ms |
| 100ms 초과 프레임 | 1 | 0 | |

귀신도 같은 모양이다 — 최초 등장 최악 **78.9 ms** → 두 번째 **36.1 ms**.

### 읽는 법

`MonsterActor.Use()` 는 같은 개체면 다시 읽지 않는다(이미 그렇게 되어 있다).
문제는 **그 "처음"이 점프스케어가 시작되는 바로 그 순간**이라는 것이다.
88.8 ms 는 `GD.Load<PackedScene>` + `Instantiate` + 위젯 숨김 재귀 + `FitToHeight`
(모든 메시의 AABB 계산)가 한 프레임 안에서 도는 시간이다.

남는 31 ms(2회차)와 귀신 1회차의 추가 42 ms 는 모델 로드가 아니다 — 셰이더 최초
컴파일 · 머티리얼 생성 · 텍스처 GPU 업로드 쪽으로 보이며, 이건 `Instantiate` 만
미리 해 둔다고 사라지지 않는다(지시서 2-2 가 짚은 그대로다).

### 괴물 배우(MonsterActor)가 몇 벌인가

같은 FBX 를 **최대 5곳**이 각자 들고 있다 — `HorrorDirector._faceActor`,
`AdminDeathDirector._actor`(**사망하는 순간 `new` 한다**), `FacilityCctvWorld` 의
`_monster`/`_scare`/`_haunt`, `PresenceDirector._body`.
각각 처음 쓰일 때 따로 88 ms 를 낸다.

## G. 측정 규칙 — 이 기계는 돌릴수록 느려진다

작업 중에 알아낸 것이고, **앞으로의 모든 성능 비교에 적용해야 한다.**

같은 빌드로 연속 측정했을 때:

| 회차 | 근무 중 · CCTV 켜짐 |
|---|---|
| 1 (차가울 때) | 30.1 FPS |
| 5 | 22.5 FPS |
| 8~11 | **12~14 FPS** |

i3-10110U 노트북이라 30분쯤 연속으로 돌리면 열로 클럭이 내려간다. 그래서:

- **다른 세션에서 잰 "전" 과 "후" 를 직접 비교하면 안 된다.** 변경 효과보다 발열
  드리프트가 크다.
- 비교는 **같은 세션 안에서 번갈아**(A/B/A/B) 재야 한다.
  `PerfBaselineRun` 에 `nowarm` 인자를 두어 준비 기능만 끄고 같은 빌드로 교차 측정한다.
- 측정 사이에 기계를 식힌다.
- 프레임 수치보다 **코드 구간 시간**(`MonsterLoad` 등)이 발열에 덜 흔들린다 —
  같은 프로세스 안에서 "처음 한 번"과 "두 번째"를 비교하기 때문이다.

## H. 코드에서 확인한 구조 문제 (아직 측정 전)

- `ControlRoom3DController.RenderScale` 이 **static 필드에 캐시되고 무효화가 없다**.
  실행 중 품질을 바꿔도 이미 만들어진 SubViewport 크기가 그대로다 → 지시서 4번의
  의심이 코드상 사실이다.
- `CorridorDef`/`CCTVMonitorView` 등은 이번 측정 범위 밖.
